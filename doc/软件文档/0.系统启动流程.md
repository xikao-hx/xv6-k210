# 系统启动流程

本文结合当前仓库代码，说明 xv6_k210 从 RustSBI 启动、进入内核，到运行首个用户进程和 shell 的完整流程。项目同时支持 QEMU `virt` 与 K210；两者共享内核主体，但装载方式、入口地址、中断路径和磁盘驱动不同。

## 1. 启动链路总览

```text
上电或启动 QEMU
  -> RustSBI（M 模式）
  -> 设置异常/中断委托并切换到 S 模式
  -> entry_qemu.S:_entry 或 entry_k210.S:_start
  -> main(hartid, dtb_pa)
  -> hart 0 完成全局初始化，其他 hart 完成本地初始化
  -> scheduler()
  -> initcode -> exec("/init") -> init -> exec("sh")
```

启动过程中涉及三个 RISC-V 特权级：RustSBI 运行在 M 模式，内核运行在 S 模式，普通用户程序运行在 U 模式。内核启动后仍通过 SBI `ecall` 请求 RustSBI 设置定时器、发送 IPI 或提供其他机器态服务。

## 2. 构建产物与平台差异

`Makefile` 通过 `platform` 选择目标平台，当前默认值是 `k210`。建议执行命令时显式指定：

```bash
make build platform=qemu
make build platform=k210
```

主要构建产物：

| 产物 | 用途 |
| --- | --- |
| `target/kernel` | 带 ELF 信息的内核映像 |
| `target/kernel.asm` | 内核反汇编，可用于定位早期启动问题 |
| `target/kernel.sym` | 内核符号表 |
| `target/fs.img` | 包含用户程序的 FAT32 文件系统映像 |
| `target/kernel.bin` | K210 使用的内核裸二进制 |
| `target/k210.bin` | RustSBI 与内核合并后的 K210 映像 |

平台相关选择：

| 项目 | QEMU | K210 |
| --- | --- | --- |
| 入口文件 | `kernel/entry_qemu.S` | `kernel/entry_k210.S` |
| 链接脚本 | `linker/qemu.ld` | `linker/k210.ld` |
| RustSBI | `bootloader/sbi-qemu` | `bootloader/sbi-k210` |
| 内核入口地址 | `0x80200000` | `0x80020000` |
| 磁盘驱动 | VirtIO block | SPI SD 卡 |
| 平台宏 | 定义 `QEMU` | 不定义 `QEMU` |

`ENTRY_OBJ` 位于内核目标文件列表首位，使平台入口代码位于链接后 `.text` 的开头，并与 RustSBI 跳转到内核起始地址的方式保持一致。

## 3. RustSBI 固件阶段

RustSBI 是内核之前运行的机器态固件。它初始化机器态环境，设置异常和中断委托，将 `mstatus.MPP` 设置为 Supervisor，并通过 `mret` 进入内核。

### 3.1 QEMU

`make run platform=qemu` 使用的关键参数为：

```text
-machine virt
-bios bootloader/sbi-qemu
-kernel target/kernel
-m 8M
-smp 2
-nographic
-drive file=target/fs.img,...
-device virtio-blk-device,...
```

QEMU 加载 RustSBI 与内核 ELF。RustSBI 将内核入口设置为 `0x80200000`。进入内核时，`a0` 保存当前 `hartid`，`a1` 保存 QEMU 提供的设备树地址 `dtb_pa`。

### 3.2 K210

K210 使用合并后的裸二进制。`make run platform=k210` 的关键步骤为：

```text
target/kernel -> objcopy -> target/kernel.bin
bootloader/sbi-k210 -> objcopy -> target/k210.bin
kernel.bin 写入 k210.bin 的 128 KiB 偏移
tools/kflash.py 烧写并启动 k210.bin
```

对应的内存布局为：

```text
0x80000000              RustSBI
0x80020000（偏移 128K） xv6 内核
```

K210 RustSBI 将内核入口设置为 `0x80020000`，再进入 S 模式。它传入 `a1` 的值是固件中的固定占位值，当前内核也没有使用 `dtb_pa`。

如果修改了 RustSBI 源码，需要单独重建固件：

```bash
make RUSTSBI platform=qemu
make RUSTSBI platform=k210
```

## 4. 内核汇编入口

### 4.1 QEMU `_entry`

`kernel/entry_qemu.S` 根据 `a0` 中的 hartid 计算当前 hart 的启动栈：

```text
栈偏移 = (hartid + 1) << 14
       = (hartid + 1) * 16 KiB
```

入口设置 `sp` 后调用 `main(a0, a1)`；如果 `main()` 意外返回，则停留在死循环。

### 4.2 K210 `_start`

K210 入口同样为每个 hart 设置 16 KiB 启动栈。由于 K210 内核通过 `objcopy` 转为裸二进制，ELF 中 `NOBITS` 类型的 `.bss` 不会出现在映像中，因此入口需要主动清零 `.bss`：

```text
hart 0：清零 [__bss_start, __bss_end)
        设置 bss_ready = 1

其他 hart：等待 bss_ready
           清零完成后进入 main()
```

由 hart 0 独占清零操作，可以避免其他 hart 在清零完成前使用全局变量或启动栈。

## 5. `main()`：内核初始化

所有 hart 都会进入 `kernel/main.c:main()`。函数先将 `hartid` 的低位写入 `tp`，后续 `cpuid()` 和 `mycpu()` 通过 `tp` 识别当前 CPU。

### 5.1 hart 0 全局初始化

| 顺序 | 调用 | 作用 |
| --- | --- | --- |
| 1 | `plicinithart()` | 设置本 hart 的 PLIC threshold，清除设备中断 enable 位 |
| 2 | `consoleinit()`、`printfinit()` | 初始化控制台和内核输出 |
| 3 | `kinit()` | 初始化物理页分配器 |
| 4 | `kvminit()` | 创建内核 Sv39 页表并映射内存和 MMIO |
| 5 | `kvminithart()` | 写 `satp`、刷新 TLB 并启用分页 |
| 6 | `procinit()` | 初始化进程表和 CPU 调度结构 |
| 7 | `trapinit()`、`trapinithart()` | 初始化 trap，安装本 hart trap 向量和定时器 |
| 8 | `binit()`、`fileinit()` | 初始化 buffer cache 和文件表 |
| 9 | 各类 `*dev_init()` | 注册通用设备以及 K210 外设 |
| 10 | `disk_init()` | QEMU 初始化 VirtIO，K210 初始化 SD 卡 |
| 11 | `userinit()` | 创建第一个可运行用户进程 |

K210 在 trap 初始化后还会调用 `sbi_set_mie()`。K210 的 PLIC 外部中断先到达 M 模式，再由 RustSBI 转发给 S 模式；QEMU 使用 PLIC 的 S 模式 context。

### 5.2 页表建立

`kvminit()` 创建内核页表，主要映射：

- 内核代码：可读、可执行；
- 内核数据和可用物理内存：可读、可写；
- CLINT、PLIC、串口等 MMIO 区域；
- QEMU 的 VirtIO MMIO，或 K210 的 GPIOHS、DMAC、FPIOA、SPI、I2C 等寄存器；
- 位于高虚拟地址的 trampoline 页面。

`kvminithart()` 将页表地址与 Sv39 模式写入 `satp`，再执行 `sfence.vma`，此后 CPU 使用内核页表运行。

### 5.3 trap 与中断初始化

`trapinithart()` 的关键操作为：

```c
w_stvec((uint64)kernelvec);
w_sstatus(r_sstatus() | SSTATUS_SIE);
w_sie(r_sie() | SIE_SEIE | SIE_SSIE | SIE_STIE);
sbi_set_timer(r_time() + INTERVAL);
```

其作用依次为：

1. 将内核态 trap 入口设置为 `kernelvec`；
2. 打开 S 模式全局中断开关；
3. 打开 S 模式外部、软件和定时器中断分类开关；
4. 通过 SBI 设置第一次时钟中断。

当前时钟频率配置为 200 Hz，即约每 5 ms 产生一次 tick。时钟中断会增加 `ticks`、唤醒等待者并安排下一次时钟中断。

外部设备还需要通过 IRQ 注册层设置 PLIC priority 和 enable。只打开 `sstatus.SIE` 与 `sie.SEIE`，并不能启用某个具体设备中断。

### 5.4 多核同步

hart 0 完成全局初始化后，通过 SBI IPI 接口通知其他 hart，执行内存屏障，并将全局变量 `started` 设置为 1。

其他 hart 等待 `started`，随后执行 `kvminithart()`、`trapinithart()` 并进入 `scheduler()`。这样全局结构只初始化一次，每个 hart 只配置自己的页表寄存器、trap 向量和定时器。

## 6. 从首个进程到 shell

`userinit()` 创建 PID 1，把内嵌的 `initcode` 放到用户虚拟地址 0，并设置：

```text
epc = 0
sp  = PGSIZE
state = RUNNABLE
```

所有 CPU 随后进入 `scheduler()`。第一次调度该进程时会进入 `forkret()`：

1. 在普通进程上下文中调用 `fat32_init()`；
2. 将当前工作目录设置为 `/`；
3. 通过 `usertrapret()` 和 trampoline 切换至用户页表；
4. 执行 `sret`，从 S 模式进入 U 模式。

`initcode` 随后调用 `exec("/init", argv)`。文件系统中的 `/init` 来自 `user/init.c`，它会创建 `/dev` 及设备节点，打开 `/dev/console` 作为标准输入输出，然后 `fork()` 并执行 `sh`。shell 退出后，`init` 会重新启动它。

至此系统启动完成。

## 7. QEMU / K210 启动方法

**QEMU启动：**

构建、生成文件系统并启动：

```bash
make run platform=qemu
```

QEMU 通过 `-nographic` 将串口连接到当前终端，通常使用 `Ctrl-a x` 退出。

仅构建内核和文件系统：

```bash
make build platform=qemu
make fs platform=qemu
```

**K210启动：**

K210 从 SPI Flash 运行 RustSBI 和内核，根文件系统位于 SD 卡。先生成并写入文件系统：

```bash
make fs platform=k210
make sdcard platform=k210 dev-sd=/dev/sdX
```

`/dev/sdX` 必须替换为 SD 卡整盘设备。该命令会覆盖目标设备，执行前必须确认设备名。也可以使用 UART 下载板端文件系统：

```bash
make download platform=k210
```

烧写并启动内核：

```bash
make run platform=k210 CONSOLE_PORT=/dev/ttyUSB0
```

只打开串口终端：

```bash
make boot CONSOLE_PORT=/dev/ttyUSB0
```

默认控制台波特率为 115200。

## 8. 外部中断路径

**PLIC的外部中断使能，都在 irq handler 注册的时候完成**

**QEMU：**
```c
外设
  ↓
PLIC
  ↓  优先级、enable、threshold 检查
CPU 的 S 模式外部中断请求（sip.SEIP）
  ↓  sie.SEIE：外部中断的分类开关
  ↓  sstatus.SIE：S 模式中断总开关
CPU 进入中断处理程序
```

**K210：** 软件中断代理

```text
外设
  ↓
PLIC 的 M 模式 context
  ↓  priority、M-mode enable、threshold 检查
CPU 产生 M 模式外部中断（Machine External Interrupt）
  ↓  mie.MEIE：M 模式外部中断开关
RustSBI 进入 MachineExternal 中断处理
  ↓  stval = 9，设置 mip.SSIP，并暂时关闭 M 模式外部中断
CPU 产生 S 模式软件中断（scause = 0x8000000000000001）
  ↓  sie.SSIE：S 模式软件中断分类开关
  ↓  sstatus.SIE：S 模式中断总开关
内核进入 kernelvec -> kerneltrap() -> devintr()
  ↓  通过 scause 和 stval == 9 识别为转发的外部中断
plic_claim() -> irq_dispatch() -> plic_complete()
  ↓
清除 sip.SSIP，并通过 sbi_set_mie() 重新打开 M 模式外部中断
```

K210 使用的 RISC-V 特权规范版本没有 S 模式外部中断，因此不能像 QEMU 一样由 PLIC 直接产生 `sip.SEIP`。项目让 PLIC 使用 M 模式 context，由 RustSBI 把 Machine External Interrupt 转换成 S 模式软件中断；`stval = 9` 是内核识别这种转发中断的标记。因此 K210 外部设备中断依赖的是 `sie.SSIE`，而不是 `sie.SEIE`。

## 9. 常见启动故障

### 9.1 没有任何串口输出

- 检查 RustSBI 是否正确加载；
- K210 检查串口设备、权限和接线；
- 检查 K210 内核是否位于合并映像的 128 KiB 偏移；
- 对照 `target/kernel.asm` 检查 `_entry` 或 `_start`；
- 确认链接地址为 QEMU `0x80200000` 或 K210 `0x80020000`。

### 9.2 有 RustSBI 输出，但没有内核启动信息

重点检查 RustSBI 跳转地址、入口对象链接顺序、启动栈，以及 K210 的 `.bss` 清零流程。RustSBI 中的硬编码入口必须与对应链接脚本一致。

### 9.3 停在磁盘或文件系统初始化

- QEMU 检查 `target/fs.img` 和 VirtIO 参数；
- K210 检查 SD 卡、SPI/FPIOA 接线和 DMAC 初始化；
- 确认文件系统中包含 `/init` 和 `sh`；
- `fat32_init()` 在首个进程的 `forkret()` 中执行，故障可能发生在调度器启动之后。

### 9.4 没有时钟或设备中断

依次检查：

```text
设备产生中断
  -> PLIC priority 非零
  -> 目标 hart/context 的 PLIC enable 已设置
  -> PLIC threshold 低于中断优先级
  -> sie.SEIE 或 sie.STIE 已设置
  -> sstatus.SIE 已设置
  -> stvec 指向有效 trap 入口
```

K210 还需检查 `sbi_set_mie()` 是否打开 M 模式外部中断，以及 RustSBI 是否完成向 S 模式的转发。
