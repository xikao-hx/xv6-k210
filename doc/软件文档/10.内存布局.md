# 内存布局

## 1. 概述

当前内核同时维护三类页表：

1. `p->pagetable`：用户页表，用户态运行时使用；
2. `kernel_pagetable`：全局内核页表，启动、scheduler 和 CPU 没有运行用户进程时使用；
3. `p->kpagetable`：每进程用户内核页表，进程进入内核后使用。

三张页表可以在相同虚拟地址上映射不同内容。例如，`0x3F_FFFF_D000` 在用户页表中是 `SIGTRAMP`，在每进程用户内核页表中则是当前进程的内核栈。

主要边界如下：

| 名称 | 地址或大小 | 含义 |
| --- | ---: | --- |
| `PGSIZE` | `0x1000` | 页大小，4 KiB |
| `MAXUVA` | `0x8000_0000` | 普通用户地址排他上限 |
| `USER_STACK_TOP` | `0x8000_0000` | 用户栈顶 |
| `USER_STACK_SIZE` | `0x0010_0000` | 用户栈预留区大小，1 MiB |
| `USER_STACK_BOTTOM` | `0x7FF0_0000` | 用户栈预留区下界 |
| `USER_STACK_GUARD` | `0x7FF0_0000` | 永不映射的栈 guard page |
| `USER_STACK_START` | `0x7FF0_1000` | 用户栈可用区起点 |
| `MMAP_TOP` | `0x7FF0_0000` | mmap 排他上界 |
| `VIRT_OFFSET` | `0x3F_0000_0000` | 设备物理地址到内核虚拟地址的偏移 |
| `SIGTRAMP` | `0x3F_FFFF_D000` | 用户信号返回代码页 |
| `TRAPFRAME` | `0x3F_FFFF_E000` | 用户页表中的 trapframe 页 |
| `TRAMPOLINE` | `0x3F_FFFF_F000` | 用户态/内核态切换代码页 |
| `MAXVA` | `0x40_0000_0000` | Sv39 软件使用的排他上限 |

`MAXUVA` 与 `MAXVA` 的职责不同：

- `MAXUVA` 限制普通用户指针、ELF、heap、mmap 和用户栈；
- `MAXVA` 只表示当前 Sv39 实现接受的虚拟地址范围；
- `SIGTRAMP`、`TRAPFRAME` 和 `TRAMPOLINE` 是位于 `MAXUVA` 以上的特殊映射，不属于普通用户地址区。

## 2. 用户页表 `p->pagetable`

用户页表供用户态执行使用。它包含 ELF、heap、mmap、固定高地址用户栈以及页表顶部的三个特殊页面。

```text
低地址

0x0000_0000      ┌──────────────────────────────┐
                 │ ELF text / data / bss       │
                 │ 当前实现为 User R/W/X       │
                 ├──────────────────────────────┤
                 │ heap (sbrk)                ↑ │
                 │ 页面按需分配                 │
                 ├──────────────────────────────┤ ← p->sz
                 │                              │
                 │        unused / unmapped     │
                 │                              │
                 ├──────────────────────────────┤ ← 最低 VMA，heap 动态上限
                 │ 后创建或复用空洞的 mmap VMA  │
                 │ 已 fault/populate 的页才映射 │
                 ├──────────────────────────────┤
                 │ 先创建的 mmap VMA          ↓ │
                 │ mmap 从高地址向低地址分配    │
0x7FF0_0000      ├──────────────────────────────┤ ← MMAP_TOP
                 │ user stack guard             │
                 │ 4 KiB，永不映射              │
0x7FF0_1000      ├──────────────────────────────┤ ← USER_STACK_START
                 │                              │
                 │ sparse user stack          ↓ │
                 │ 缺页时按需分配               │
                 │                              │
0x7FFF_F000      ├──────────────────────────────┤
                 │ initial user stack page      │
                 │ exec 时预分配，User RW       │
0x8000_0000      ├──────────────────────────────┤ ← USER_STACK_TOP / MAXUVA
                 │                              │
                 │      reserved / unmapped     │
                 │                              │
                 │ 普通用户指针不得进入此区域   │
                 │                              │
0x3F_FFFF_D000   ├──────────────────────────────┤ ← SIGTRAMP
                 │ SIGTRAMP，User R-X           │
0x3F_FFFF_E000   ├──────────────────────────────┤ ← TRAPFRAME
                 │ TRAPFRAME                    │
                 │ Supervisor RW，非 PTE_U      │
0x3F_FFFF_F000   ├──────────────────────────────┤ ← TRAMPOLINE
                 │ TRAMPOLINE                   │
                 │ Supervisor R-X，非 PTE_U     │
0x40_0000_0000   └──────────────────────────────┘ ← MAXVA

高地址
```

### 2.1 ELF 与 heap

`p->sz` 只表示低地址 ELF/heap 区的末尾，不再包含用户栈或 VMA。heap 通过 `sbrk()` 向高地址增长，其动态上限是最低 VMA 的起点；没有 VMA 时，上限为 `MMAP_TOP`。

heap 虚拟区间可以先扩大而不立即分配物理页。第一次访问未驻留 heap 页时，统一缺页路径负责分配并同步页表。

### 2.2 mmap 区域

mmap 的可用范围是：

```text
[PGROUNDUP(p->sz), MMAP_TOP)
```

VMA 从 `MMAP_TOP` 向低地址选择最高可用空洞。VMA 元数据存在不代表每一页都已建立 PTE：普通文件和匿名映射可按需 fault，设备映射也可以通过 populate 提前建立全部页面。

heap 和 mmap 从区间两端相向增长：

```text
heap  ───────────────────────→
                              unused
                     ←──────────────── mmap
```

两侧都会检查对方边界，不能相互穿越。

### 2.3 固定高地址用户栈

用户栈预留区为 1 MiB：

```text
[0x7FF0_0000, 0x8000_0000)
```

其中：

- `[0x7FF0_0000, 0x7FF0_1000)` 是 guard page，永不映射；
- `[0x7FF0_1000, 0x8000_0000)` 是可用栈区；
- exec 只预分配顶部一页 `[0x7FFF_F000, 0x8000_0000)`；
- 其余栈页在缺页时按需分配；
- fork 只复制已经驻留的栈页，并沿用 COW。

## 3. 全局内核页表 `kernel_pagetable`

全局内核页表供启动阶段、scheduler 和当前 CPU 没有运行用户进程时使用。它包含内核恒等映射、高地址 MMIO 和 trampoline，不包含用户页、进程内核栈、`SIGTRAMP` 或 `TRAPFRAME`。

```text
低地址

0x0000_0000      ┌──────────────────────────────┐
                 │                              │
                 │           unmapped           │
                 │                              │
0x8000_0000      ├──────────────────────────────┤ ← MAXUVA
                 │ platform gap                 │
                 │                              │
KERNBASE         ├──────────────────────────────┤
                 │ kernel text                  │
                 │ VA == PA，R-X                │
                 ├──────────────────────────────┤ ← etext
                 │ kernel data / bss            │
                 │ allocator-managed RAM        │
                 │ VA == PA，RW                 │
0x8060_0000      ├──────────────────────────────┤ ← PHYSTOP
                 │                              │
                 │           unmapped           │
                 │                              │
0x3F_0000_0000   ├──────────────────────────────┤ ← VIRT_OFFSET
                 │ 此地址本身没有建立映射       │
                 │                              │
0x3F_0200_0000   ├──────────────────────────────┤
                 │ CLINT                        │
                 │ PA 0x0200_0000               │
                 │ size 64 KiB，RW              │
0x3F_0201_0000   ├──────────────────────────────┤
                 │           unmapped           │
0x3F_0C00_0000   ├──────────────────────────────┤
                 │ PLIC                         │
                 │ PA 0x0C00_0000               │
                 │ size 4 MiB，RW               │
0x3F_0C40_0000   ├──────────────────────────────┤
                 │                              │
                 │ QEMU 或 K210 设备映射         │
                 │ 具体内容见第 5 节             │
                 │                              │
                 ├──────────────────────────────┤
                 │                              │
                 │           unmapped           │
                 │                              │
0x3F_FFFF_D000   ├──────────────────────────────┤
                 │ unmapped                     │
                 │ 全局页表不映射进程内核栈     │
0x3F_FFFF_E000   ├──────────────────────────────┤
                 │ unmapped                     │
                 │ 全局页表没有 TRAPFRAME       │
0x3F_FFFF_F000   ├──────────────────────────────┤ ← TRAMPOLINE
                 │ TRAMPOLINE，R-X              │
0x40_0000_0000   └──────────────────────────────┘ ← MAXVA

高地址
```

平台相关的恒等映射起点如下：

| 平台 | `KERNBASE` | `PHYSTOP` |
| --- | ---: | ---: |
| K210 | `0x8002_0000` | `0x8060_0000` |
| QEMU | `0x8020_0000` | `0x8060_0000` |

`[KERNBASE, etext)` 映射为可读、可执行；`[etext, PHYSTOP)` 映射为可读、可写。

## 4. 每进程用户内核页表 `p->kpagetable`

进程执行系统调用、中断或异常进入内核后使用自己的 `p->kpagetable`。它包含全局内核映射，并额外加入当前进程用户页面的 supervisor 镜像和一页私有内核栈。

```text
低地址

0x0000_0000      ┌──────────────────────────────┐
                 │ ELF text/data/bss 镜像       │
                 │ 与用户页表指向相同物理页     │
                 │ 清除 PTE_U                   │
                 ├──────────────────────────────┤
                 │ heap 已驻留页面镜像        ↑ │
                 │ lazy heap 未分配页不映射     │
                 ├──────────────────────────────┤ ← p->sz
                 │                              │
                 │           unmapped           │
                 │                              │
                 ├──────────────────────────────┤ ← 最低 VMA
                 │ VMA 已驻留页面镜像           │
                 │ 未 fault/populate 页不映射   │
                 ├──────────────────────────────┤
                 │ 先创建的 VMA 镜像          ↓ │
0x7FF0_0000      ├──────────────────────────────┤ ← MMAP_TOP
                 │ user stack guard             │
                 │ 不映射                       │
0x7FF0_1000      ├──────────────────────────────┤
                 │ 用户栈已驻留页面镜像       ↓ │
                 │ 与用户页表指向相同物理页     │
                 │ 清除 PTE_U                   │
0x8000_0000      ├──────────────────────────────┤ ← MAXUVA
                 │ platform gap                 │
                 │                              │
KERNBASE         ├──────────────────────────────┤
                 │ kernel text                  │
                 │ VA == PA，R-X                │
                 ├──────────────────────────────┤ ← etext
                 │ kernel data / bss            │
                 │ allocator-managed RAM        │
                 │ VA == PA，RW                 │
0x8060_0000      ├──────────────────────────────┤ ← PHYSTOP
                 │                              │
                 │           unmapped           │
                 │                              │
0x3F_0000_0000   ├──────────────────────────────┤ ← VIRT_OFFSET
                 │ 此地址本身不映射             │
                 │                              │
0x3F_0200_0000   ├──────────────────────────────┤
                 │ CLINT high-VA mapping        │
                 │ PA 0x0200_0000，64 KiB       │
0x3F_0201_0000   ├──────────────────────────────┤
                 │           unmapped           │
0x3F_0C00_0000   ├──────────────────────────────┤
                 │ PLIC high-VA mapping         │
                 │ PA 0x0C00_0000，4 MiB        │
0x3F_0C40_0000   ├──────────────────────────────┤
                 │                              │
                 │ QEMU 或 K210 设备映射         │
                 │ 与全局内核页表完全相同       │
                 │                              │
                 ├──────────────────────────────┤
                 │                              │
                 │           unmapped           │
                 │                              │
0x3F_FFFF_D000   ├──────────────────────────────┤ ← KSTACK(0)
                 │ current process kernel stack │
                 │ 4 KiB，RW                    │
                 │ 每进程映射不同物理页         │
0x3F_FFFF_E000   ├──────────────────────────────┤
                 │ kernel stack guard           │
                 │ 4 KiB，不映射                │
0x3F_FFFF_F000   ├──────────────────────────────┤ ← TRAMPOLINE
                 │ TRAMPOLINE，R-X              │
0x40_0000_0000   └──────────────────────────────┘ ← MAXVA

高地址
```

用户内核页表中的用户镜像具有以下特点：

- 与用户页表指向相同物理页；
- 清除 `PTE_U`，只允许 supervisor 访问；
- 只镜像实际存在的稀疏页；
- 用户页表拥有用户物理页，用户内核页表只拥有镜像 PTE；
- 释放时必须先解除内核镜像，再由用户页表释放物理页。

每个进程都有独立的 `p->kpagetable`，因此所有进程都可以使用固定虚拟地址 `KSTACK(0) == 0x3F_FFFF_D000` 映射各自不同的内核栈物理页。

## 5. 高虚拟地址 MMIO

设备 CPU 访问地址统一按下式计算：

```text
设备虚拟地址 = 设备物理地址 + VIRT_OFFSET
VIRT_OFFSET  = 0x3F_0000_0000
```

`VIRT_OFFSET` 本身只是转换常量，不代表从该地址开始整段连续映射。只有下面明确列出的设备区间存在叶子映射。

### 5.1 公共设备

QEMU 和 K210 都建立以下映射：

```text
0x3F_0200_0000   ┌──────────────────────────────┐
                 │ CLINT                        │
                 │ PA 0x0200_0000               │
                 │ size 0x0001_0000             │
0x3F_0201_0000   └──────────────────────────────┘

0x3F_0C00_0000   ┌──────────────────────────────┐
                 │ PLIC                         │
                 │ PA 0x0C00_0000               │
                 │ size 0x0040_0000             │
0x3F_0C40_0000   └──────────────────────────────┘
```

### 5.2 QEMU 设备

```text
0x3F_1000_0000   ┌──────────────────────────────┐
                 │ UARTHS                       │
                 │ PA 0x1000_0000，4 KiB        │
0x3F_1000_1000   ├──────────────────────────────┤
                 │ VirtIO MMIO                  │
                 │ PA 0x1000_1000，4 KiB        │
0x3F_1000_2000   └──────────────────────────────┘
```

### 5.3 K210 设备

| 设备 | 物理地址 | 内核虚拟地址 | 长度 |
| --- | ---: | ---: | ---: |
| UARTHS | `0x3800_0000` | `0x3F_3800_0000` | 4 KiB |
| GPIOHS | `0x3800_1000` | `0x3F_3800_1000` | 4 KiB |
| DMAC | `0x5000_0000` | `0x3F_5000_0000` | 4 KiB |
| GPIO | `0x5020_0000` | `0x3F_5020_0000` | 4 KiB |
| UART0 | `0x5021_0000` | `0x3F_5021_0000` | 4 KiB |

| UART2 | `0x5023_0000` | `0x3F_5023_0000` | 4 KiB |
| SPI_SLAVE | `0x5024_0000` | `0x3F_5024_0000` | 4 KiB |
| I2C0 | `0x5028_0000` | `0x3F_5028_0000` | 4 KiB |

## 6. 三张页表对照

### 6.1 主要区域

| 区域 | 用户页表 | 全局内核页表 | 用户内核页表 |
| --- | --- | --- | --- |
| ELF/heap | 用户映射 | 不映射 | supervisor 镜像 |
| mmap VMA | 用户映射 | 不映射 | supervisor 镜像 |
| 用户栈 | 用户映射 | 不映射 | supervisor 镜像 |
| 用户栈 guard | 不映射 | 不映射 | 不映射 |
| 内核 text/data | 不映射 | 恒等映射 | 恒等映射 |
| 高地址 MMIO | 不映射 | `PA + VIRT_OFFSET` | `PA + VIRT_OFFSET` |
| 进程内核栈 | 不映射 | 不映射 | 每进程独立映射 |

### 6.2 页表顶部

```text
虚拟地址          用户页表              全局内核页表       用户内核页表
────────────────────────────────────────────────────────────────────────
0x3F_FFFF_D000    SIGTRAMP              unmapped           kernel stack
0x3F_FFFF_E000    TRAPFRAME             unmapped           stack guard
0x3F_FFFF_F000    TRAMPOLINE            TRAMPOLINE         TRAMPOLINE
0x40_0000_0000    MAXVA                 MAXVA              MAXVA
```

这些地址位于不同页表中，因此相同虚拟地址映射不同内容是合法的。

## 7. 页表切换

CPU 的 `satp` 是每个 hart 独立的状态。页表切换关系如下：

```text
内核启动 / scheduler
        │
        │ kvminithart()
        ▼
kernel_pagetable
        │
        │ scheduler 选中进程
        │ ukvminithart(p->kpagetable)
        ▼
p->kpagetable
        │
        │ trampoline 返回用户态
        ▼
p->pagetable
        │
        │ trap / syscall / interrupt
        ▼
p->kpagetable
        │
        │ 进程让出 CPU，返回 scheduler
        ▼
kernel_pagetable
```

每个次级 hart 都必须在访问 `UARTHS_V` 等高虚拟 MMIO 地址之前自行执行 `kvminithart()`。hart0 建立好全局页表并不能自动修改其他 hart 的 `satp`。

## 8. 生命周期与所有权

低地址 ELF/heap、固定用户栈和 VMA 是三个独立区域：

- `[0, p->sz)` 只用于 ELF/heap 的复制和释放；
- 用户栈由 `uvm_stack_init()`、`uvm_stack_copy()`、`uvm_stack_sync()` 和 `uvm_stack_unmap()` 管理；
- VMA 由 `vma_fork()`、`vma_unmap()` 和 `vma_destroy_all()` 管理；
- 用户物理页由用户页表拥有；
- 用户内核页表只维护 supervisor 镜像，不拥有用户物理页；
- heap 收缩、munmap、exec 和进程释放必须先解除用户内核页表镜像，再释放用户页表中的物理页。

这种拆分避免重新使用 `[0, p->sz)` 表示整个用户地址空间，也避免固定高栈和稀疏 VMA 在 fork、exec、exit 时被遗漏。

## 9. 相关源码

- `kernel/include/memlayout.h`：地址常量、设备 PA/VA 和平台 `KERNBASE`；
- `kernel/include/mmap.h`：`MMAP_TOP` 和 VMA 定义；
- `kernel/include/riscv.h`：`PGSIZE`、`MAXVA` 和 Sv39 页表格式；
- `kernel/vm/vm.c`：全局内核页表、用户内核页表、栈和用户镜像管理；
- `kernel/vm/mmap.c`：VMA 地址选择、fault、populate、fork 和解除映射；
- `kernel/proc/proc.c`：进程页表创建、释放、fork 和 scheduler 页表切换；
- `kernel/proc/exec.c`：ELF 加载、固定用户栈创建和地址空间替换。
