# K210 I2C、SPI、UART 寄存器与驱动学习指南

本文面向本仓库的 K210 平台代码，目标不是罗列所有寄存器，而是建立下面这条完整认识：

> 外设协议 → K210 控制器 → MMIO 寄存器 → 中断/DMA → xv6 驱动接口 → 板级设备

## 1. 阅读寄存器手册前必须理解的概念

### 1.1 MMIO：寄存器就是特殊地址上的内存

K210 把外设寄存器映射到物理地址空间。CPU 对这些地址进行读写，就等于操作外设。

本仓库中的主要物理基址如下：

| 控制器 | 物理基址 |
|---|---:|
| UARTHS | `0x38000000` |
| UART1 | `0x50210000` |
| UART2 | `0x50220000` |
| UART3 | `0x50230000` |
| I2C0 | `0x50280000` |
| I2C1 | `0x50290000` |
| I2C2 | `0x502a0000` |
| SPI0 | `0x52000000` |
| SPI1 | `0x53000000` |
| SPI3 | `0x54000000` |

本仓库开启页表后，通过 `VIRT_OFFSET` 得到内核虚拟地址。例如：

```c
#define I2C0   0x50280000L
#define I2C0_V (I2C0 + VIRT_OFFSET)
```

寄存器的实际地址等于：

```text
寄存器地址 = 控制器基址 + 寄存器偏移
```

例如 I2C0 的 `IC_DATA_CMD` 偏移是 `0x10`，其物理地址就是 `0x50280010`。

### 1.2 为什么使用 `volatile` 结构体

本仓库把寄存器布局定义成结构体：

```c
typedef struct _i2c {
  volatile uint32_t con;       // 0x00
  volatile uint32_t tar;       // 0x04
  volatile uint32_t sar;       // 0x08
  volatile uint32_t reserved;  // 0x0c
  volatile uint32_t data_cmd;  // 0x10
} i2c_t;
```

然后把基址转换为结构体指针：

```c
volatile i2c_t *const i2c0 = (volatile i2c_t *)I2C0_V;
i2c0->tar = 0x3c;
```

`volatile` 告诉编译器：每次读取和写入都必须真的访问硬件，不能把寄存器值长期缓存到普通 CPU 寄存器中，也不能把看似重复的访问随意删除。

`volatile` 不是锁，也不保证多核并发安全。共享控制器仍需自旋锁、睡眠锁以及必要的内存屏障。

### 1.3 手册中的访问属性

| 标记 | 含义 | 驱动注意事项 |
|---|---|---|
| `R` / `RO` | 只读 | 不要写入 |
| `W` / `WO` | 只写 | 读回值可能没有意义 |
| `R/W` | 可读写 | 修改部分位时通常使用读－改－写 |
| `W1C` | 写 1 清零 | 不能用普通读－改－写清中断 |
| Read-to-clear | 读取即清除 | 读取本身有副作用，不能为了调试反复读 |
| Reserved | 保留位 | 写入时保持复位值，通常写 0 |

本仓库中 `(void)adapter->clr_tx_abrt;` 这种代码不是无意义读取，而是在读取“读清除”寄存器，从而清除中断状态。

### 1.4 驱动不只是寄存器读写

一个可以稳定工作的 K210 外设驱动通常还需要：

1. 在 SYSCTL 中打开时钟，必要时复位控制器；
2. 在 FPIOA 中把芯片引脚映射为外设信号；
3. 配置总线速率、数据格式和 FIFO；
4. 在 PLIC 中注册并启用中断；
5. 使用锁保护同一控制器上的并发传输；
6. 处理超时、FIFO 溢出、无应答等错误；
7. 数据量较大时配置 DMAC 请求源和通道；
8. 最后才是向数据寄存器读写数据。

## 2. I2C

### 2.1 协议模型

I2C 使用两根开漏信号线：

- `SCL`：时钟；
- `SDA`：数据。

开漏意味着控制器只能主动拉低信号，逻辑高电平依赖上拉电阻。没有上拉、电阻过大、总线电容过大，都会造成波形异常。

一次典型的“读取芯片寄存器”不是单纯的读，而是：

```text
START
  → 从机地址 + Write
  → 芯片内部寄存器地址
  → RESTART
  → 从机地址 + Read
  → 数据
  → NACK
  → STOP
```

这里的“芯片内部寄存器地址”是 MPU6050、SSD1306 等从设备自己的协议字段，不是 K210 的 MMIO 寄存器地址。

### 2.2 K210 I2C 常用寄存器

| 偏移 | 寄存器 | 主要功能 | 常见用法 |
|---:|---|---|---|
| `0x00` | `IC_CON` | 主从模式、速度档、7/10 位地址、重复起始 | 禁用控制器后配置主机模式、禁止从机、打开 `RESTART_EN` |
| `0x04` | `IC_TAR` | 当前目标从机地址 | 每次访问设备前写 7 位地址；10 位模式还需置对应位 |
| `0x08` | `IC_SAR` | 本机作为从机时的地址 | 只做主机驱动时通常不用 |
| `0x10` | `IC_DATA_CMD` | TX/RX FIFO 数据与读命令入口 | 写数据；或写 `CMD=1` 产生一次读请求；可附加 `STOP`、`RESTART` |
| `0x14` | `IC_SS_SCL_HCNT` | 标准速率 SCL 高电平周期数 | 和输入时钟共同决定 SCL 频率 |
| `0x18` | `IC_SS_SCL_LCNT` | 标准速率 SCL 低电平周期数 | 和 HCNT 一起配置时序 |
| `0x2c` | `IC_INTR_STAT` | 经过屏蔽后的中断状态 | ISR 中判断 `RX_FULL`、`TX_EMPTY`、`TX_ABRT`、`STOP_DET` |
| `0x30` | `IC_INTR_MASK` | 中断使能/屏蔽 | 只打开当前传输需要的中断 |
| `0x34` | `IC_RAW_INTR_STAT` | 未经过屏蔽的原始状态 | 调试硬件状态很有用 |
| `0x38` | `IC_RX_TL` | RX FIFO 中断阈值 | FIFO 数据达到阈值时产生 `RX_FULL` |
| `0x3c` | `IC_TX_TL` | TX FIFO 中断阈值 | FIFO 数据不高于阈值时产生 `TX_EMPTY` |
| `0x40`～`0x68` | `IC_CLR_*` | 清除各类中断 | 多数是读清除，必须按手册规定操作 |
| `0x6c` | `IC_ENABLE` | 启停控制器、发起中止 | 修改关键配置前先清零，配置后置 `ENABLE` |
| `0x70` | `IC_STATUS` | 控制器和 FIFO 状态 | 查询活动状态、TX 非满、TX 空、RX 非空、RX 满 |
| `0x74` | `IC_TXFLR` | TX FIFO 当前条目数 | 填 FIFO 前计算可写空间 |
| `0x78` | `IC_RXFLR` | RX FIFO 当前条目数 | 读 FIFO 前确认可读条目数 |
| `0x7c` | `IC_SDA_HOLD` | SDA 发送/接收保持时间 | 配合总线时钟满足建立/保持时间 |
| `0x80` | `IC_TX_ABRT_SOURCE` | 发送中止原因 | 判断地址 NACK、数据 NACK、仲裁丢失、控制器未启用等 |
| `0x88` | `IC_DMA_CR` | RX/TX DMA 使能 | bit0 为接收 DMA，bit1 为发送 DMA |
| `0x8c` | `IC_DMA_TDLR` | TX DMA 水位 | 控制何时请求 TX DMA |
| `0x90` | `IC_DMA_RDLR` | RX DMA 水位 | 控制何时请求 RX DMA |
| `0x9c` | `IC_ENABLE_STATUS` | 硬件实际启用状态 | 写 `IC_ENABLE` 后轮询确认状态已切换 |
| `0xf4`～`0xfc` | `IC_COMP_*` | IP 参数、版本、类型 | 探测 FIFO 深度和控制器版本，通常不参与每次传输 |

`IC_DATA_CMD` 是理解 K210 I2C 的关键：

| 位 | 名称 | 含义 |
|---:|---|---|
| `7:0` | `DAT` | 写操作时是待发送数据；读寄存器时是收到的数据 |
| `8` | `CMD` | `0` 表示写字节，`1` 表示产生一个读请求 |
| `9` | `STOP` | 当前字节完成后产生 STOP |
| `10` | `RESTART` | 当前命令前产生重复 START |

注意：“从 I2C 读 N 字节”仍然需要 CPU 或 DMA 向 `IC_DATA_CMD` 写 N 个 `CMD=1` 的读命令。控制器收到这些命令后才产生 SCL，得到的数据随后进入 RX FIFO。

### 2.3 轮询方式写数据

适合最初验证硬件，不适合长时间占用 CPU：

```c
disable_controller();
configure_ic_con_and_clock();
set_target_address(addr);
enable_controller();

for (i = 0; i < len; i++) {
  wait_until_tx_fifo_not_full();
  cmd = buf[i];
  if (i == len - 1)
    cmd |= I2C_DATA_CMD_STOP;
  i2c->data_cmd = cmd;
}

wait_for_stop_or_abort_with_timeout();
```

不要只等待 `TX FIFO` 变空就宣告完成。FIFO 空只表示命令已送给控制器，不一定表示总线上已经出现 STOP。通常应等待 `STOP_DET`，并同时监控 `TX_ABRT`。

### 2.4 轮询方式读数据

```c
for (i = 0; i < len; i++) {
  wait_until_tx_fifo_not_full();
  cmd = I2C_DATA_CMD_CMD;
  if (need_restart && i == 0)
    cmd |= I2C_DATA_CMD_RESTART;
  if (i == len - 1)
    cmd |= I2C_DATA_CMD_STOP;
  i2c->data_cmd = cmd;
}

for (i = 0; i < len; i++) {
  wait_until_rx_fifo_not_empty();
  buf[i] = i2c->data_cmd & 0xff;
}
```

实际驱动还必须限制尚未返回的读命令数，避免 RX FIFO 来不及排空而溢出。

### 2.5 本仓库中的 I2C 实现

初始化路径在 `i2c_dw_init()`：

- 通过 SYSCTL 打开控制器时钟；
- 清 `IC_ENABLE` 并等待 `IC_ENABLE_STATUS`；
- 配置 `IC_CON`、SCL 高低计数和 SDA hold；
- 配置 FIFO 阈值以及 DMA 水位；
- 启用控制器。

中断传输的核心路径是：

```text
i2c_transfer()
  → 设置 IC_TAR
  → 根据读/写和长度选择中断或 DMA
  → i2c_dw_xfer_msg() 填充命令 FIFO
  → I2C 中断
      TX_EMPTY：继续填 FIFO
      RX_FULL：排空 RX FIFO
      STOP_DET：读取尾部数据并完成传输
      TX_ABRT：记录错误并终止
```

板级配置目前定义了 400 kHz 控制器，并给 OLED 和 MPU6050 设置了总线号和 7 位地址。设备描述与通用控制器驱动分开，是值得保留的分层方式。

### 2.6 I2C 调试重点

| 现象 | 首先检查 |
|---|---|
| SDA/SCL 一直高 | FPIOA 是否映射、控制器时钟是否开启、是否真正向 `DATA_CMD` 写命令 |
| SDA/SCL 一直低 | 上拉、电气短路、从机卡住、控制器未复位 |
| 地址后 NACK | 7 位地址是否被错误地左移；器件是否供电；地址选择脚状态 |
| 数据阶段 NACK | 从机寄存器协议、写保护、器件忙状态 |
| `TX_ABRT` | 立即读取 `TX_ABRT_SOURCE`，不要只返回笼统的 `EIO` |
| 读操作全为 `0xff` | 是否发出了 `CMD=1` 的读命令；MISO 概念不适用于 I2C |
| 400 kHz 不稳定 | 上拉、电容、SCL 高低计数、SDA hold、逻辑分析仪波形 |

本仓库代码中有两处适合在后续专项评审时核对：

1. `i2c_write_slave_addr()` 使用 `slave_address == 10` 判断 10 位模式。这里比较的是地址值，不是地址宽度；而 `i2c_transfer()` 当前又明确只允许 7 位地址。地址 `0x0a` 可能因此被错误设置成 10 位模式。
2. 板级配置标为 400 kHz，而 `IC_CON` 使用了 `I2C_CON_SPEED(0)`。速度编码及当前 SCL 计数应依据手册和逻辑分析仪再次确认，不能只凭注释判断实际频率。

## 3. SPI

### 3.1 协议模型

标准四线 SPI 通常包含：

- `SCLK`：主机产生的串行时钟；
- `MOSI`：主机到从机；
- `MISO`：从机到主机；
- `CS/SS`：片选，通常低有效。

SPI 没有统一的设备级命令格式，也没有自动应答。W25Q64、SD 卡、屏幕等设备的命令、地址和 dummy byte 都由各自数据手册定义。

SPI 是移位式全双工总线：发出一个 frame 的同时也会收到一个 frame。因此：

- “只写”时仍可能产生无用的接收数据，必须防止 RX FIFO 溢出；
- “只读”时主机仍需发送 dummy 数据，常用 `0xff` 或 `0x00` 来产生时钟；
- 命令、地址和数据若属于同一次事务，CS 必须持续保持有效。

### 3.2 SPI Mode

| Mode | CPOL | CPHA | 空闲时钟 | 采样关系 |
|---:|---:|---:|---|---|
| 0 | 0 | 0 | 低 | 第一边沿采样 |
| 1 | 0 | 1 | 低 | 第二边沿采样 |
| 2 | 1 | 0 | 高 | 第一边沿采样 |
| 3 | 1 | 1 | 高 | 第二边沿采样 |

模式错误的典型表现是：逻辑分析仪能看到时钟和数据，但读出的 ID 或数据总差一位、随机变化或全错。

### 3.3 K210 SPI 常用寄存器

| 偏移 | 寄存器 | 主要功能 | 常见用法 |
|---:|---|---|---|
| `0x00` | `CTRLR0` | 数据位宽、SPI frame 格式、CPOL/CPHA、传输模式 | 配置 8/16/32 位、Mode 0～3、收发模式 |
| `0x04` | `CTRLR1` | 接收数据 frame 数 | receive-only / EEPROM-read 模式使用，通常写 `NDF-1` |
| `0x08` | `SSIENR` | 控制器使能 | 改关键配置前清零，传输前置 1 |
| `0x0c` | `MWCR` | Microwire 配置 | 标准 SPI 一般不用 |
| `0x10` | `SER` | 选择硬件片选 | bit N 对应第 N 个 slave select；写 0 取消片选 |
| `0x14` | `BAUDR` | SCLK 分频 | `SCLK ≈ 输入时钟 / BAUDR`；分频值须满足手册范围和偶数要求 |
| `0x18` | `TXFTLR` | TX FIFO 中断阈值 | TX FIFO 不高于阈值时触发补充数据 |
| `0x1c` | `RXFTLR` | RX FIFO 中断阈值 | RX FIFO 高于阈值时触发读取 |
| `0x20` | `TXFLR` | TX FIFO 当前条目数 | 判断还能写多少 frame |
| `0x24` | `RXFLR` | RX FIFO 当前条目数 | 判断能读多少 frame |
| `0x28` | `SR` | BUSY 和 FIFO 状态 | 判断总线是否仍在移位、TX/RX 是否可用 |
| `0x2c` | `IMR` | 中断屏蔽 | 使能 TX empty、RX full、overflow 等中断 |
| `0x30` | `ISR` | 屏蔽后的中断状态 | ISR 中判断当前事件 |
| `0x34` | `RISR` | 原始中断状态 | 排查“有状态但没进中断”问题 |
| `0x38`～`0x48` | `*ICR` | 中断清除 | 按具体中断读取对应 clear 寄存器 |
| `0x4c` | `DMACR` | TX/RX DMA 使能 | bit0 RX DMA，bit1 TX DMA |
| `0x50` | `DMATDLR` | TX DMA 水位 | FIFO 达到条件后请求 DMA |
| `0x54` | `DMARDLR` | RX DMA 水位 | FIFO 达到条件后请求 DMA |
| `0x60` 起 | `DR[n]` | FIFO 数据端口 | 通常读写 `DR[0]` 即可；一次访问宽度应匹配 frame 宽度 |
| `0xf0` | `RX_SAMPLE_DLY` | 输入采样延迟 | 高频或板级延迟较大时调整采样点 |
| `0xf4` | `SPI_CTRLR0` | Dual/Quad/Octal 指令、地址、等待周期配置 | 标准单线 SPI 不用；扩展模式或 XIP 才配置 |

`CTRLR0` 是 SPI 最重要也最容易配错的寄存器。对 K210 SPI0/SPI1，常用字段包括：

- `DFS_32[20:16]`：frame 位数减 1，例如 8 位写 7；
- `SPI_FRF[22:21]`：standard、dual、quad、octal；
- `SCPH` / `SCPOL`：对应 SPI Mode；
- `TMOD[9:8]`：全双工、只发送、只接收、EEPROM read。

K210 的不同 SPI 实例并非完全相同，不能把 SPI0/SPI1 的 `CTRLR0` 位偏移机械复制给 SPI3 或 SPI slave。本仓库也在 `spi_setup()` 和 `spi_set_tmod()` 中按实例选择不同位偏移。

### 3.4 一次标准全双工传输

```c
spi->ssienr = 0;
configure_ctrlr0_mode_and_width();
spi->baudr = even_divisor;
spi->txftlr = 0;
spi->rxftlr = 0;
spi->ssienr = 1;

spi->ser = 1u << chip_select;
while (frames_remain) {
  if (tx_fifo_has_room)
    spi->dr[0] = next_tx_frame;
  if (rx_fifo_has_data)
    next_rx_frame = spi->dr[0];
}
wait_until_controller_not_busy();
spi->ser = 0;
```

如果使用 GPIO 作为 CS，则 `SER` 仍可能需要选择一个内部从机以产生 SCLK，但真正的片选边沿由 GPIO 控制。仓库中的 W25Q64 就采用这种形式。

### 3.5 本仓库中的 SPI 实现

仓库驱动的主要路径：

```text
spi_transfer()
  → 获取控制器睡眠锁
  → 拉低/启用 CS
  → 禁用 SSI，设置 CTRLR0，再启用 SSI
  → 满足长度、对齐和 DMA 条件：走 DMA
    否则：走中断
      TXE：继续填 TX FIFO
      RXF：排空 RX FIFO
      RXO/TXO：记录错误并结束
  → 释放 CS
  → 释放锁
```

当前板级配置：

- SPI0：SD 卡，硬件 CS3，DMA CH0/CH1；
- SPI1：W25Q64，GPIO CS，因 DMA CH4/CH5 给 UART1 使用而关闭 DMA；
- 两者默认设备描述均为 Mode 0、8 bit、10 MHz。

`spi_read()` 会发送一串 `0xff` 来产生接收时钟；`spi_write()` 同时准备接收缓冲区以排空回传数据。这正是全双工 SPI 驱动应有的处理。

### 3.6 SPI 调试重点

| 现象 | 首先检查 |
|---|---|
| 没有 SCLK | `SSIENR`、`SER/CS`、FPIOA、TX FIFO 是否写入数据 |
| CS 有效但数据错误 | CPOL/CPHA、bit order、frame 位宽、设备最高频率 |
| 读回全 `0xff` | MISO 悬空、CS 错误、命令错误、器件未退出掉电模式 |
| 读回全 `0x00` | MISO 被拉低、引脚复用错误、电平不匹配 |
| RX FIFO overflow | 只顾写 TX 而没有同步排空 RX；中断延迟过高 |
| 最后一个字节丢失 | 只等 TX FIFO 空，没有等 `SR.BUSY` 清零就释放 CS |
| 高频正常率低 | 降低 BAUDR、调整 `RX_SAMPLE_DLY`、检查走线与地线 |

## 4. UART 与 UARTHS

### 4.1 先区分两类控制器

K210 中有两套不同的 UART 寄存器接口：

1. UART1～UART3：较完整的 DesignWare APB UART，支持 FIFO、中断、DMA、RS-485 等；对应本仓库 `uart.c`。
2. UARTHS：寄存器很少的高速控制台 UART；对应本仓库 `uarths.c`。

QEMU 平台的控制台则使用 16550A 兼容寄存器。不要把 K210 UARTHS 的寄存器布局用于 QEMU，也不要把 UART1 的 `RBR/THR/LCR` 布局用于 UARTHS。

本仓库内部宏 `UART0`、数组下标 0 实际对应手册中的 UART1，物理地址是 `0x50210000`。这是软件从 0 开始编号与手册从 1 开始编号的差异。

### 4.2 UART 帧格式

常见 `115200 8N1` 表示：

- 115200 baud；
- 8 个数据位；
- N：无奇偶校验；
- 1 个停止位。

通信双方的波特率、数据位、校验和停止位必须一致。UART 空闲线为高，起始位为低，因此 RX 输入悬空或被错误下拉时，控制器可能不断收到 `0x00` 和 framing error。

### 4.3 UART1～UART3 常用寄存器

| 偏移 | 寄存器 | 主要功能 | 重要说明 |
|---:|---|---|---|
| `0x00` | `RBR` / `THR` / `DLL` | 接收、发送或波特率低位 | `DLAB=0` 时读 RBR、写 THR；`DLAB=1` 时访问 DLL |
| `0x04` | `IER` / `DLH` | 中断使能或波特率高位 | 同样由 `LCR.DLAB` 决定含义 |
| `0x08` | `IIR` / `FCR` | 读中断原因、写 FIFO 控制 | 同一偏移读写含义不同 |
| `0x0c` | `LCR` | 数据位、停止位、校验、break、DLAB | 8N1 通常设置 DLS=3，其余格式位为 0 |
| `0x10` | `MCR` | modem/流控信号 | RTS、DTR 等；普通两线 UART 常不用 |
| `0x14` | `LSR` | 收发和错误状态 | Data Ready、Overrun、Parity、Transmitter Empty 等 |
| `0x18` | `MSR` | modem 状态 | CTS/DSR 等硬件流控相关 |
| `0x70` | `FAR` | FIFO 访问模式 | 调试/测试 FIFO，普通传输少用 |
| `0x74` | `TFR` | 直接读取发送 FIFO | 调试用途为主 |
| `0x78` | `RFW` | 直接写接收 FIFO | 调试用途为主 |
| `0x7c` | `USR` | UART 总状态 | BUSY、TX FIFO 非满/空、RX FIFO 非空/满 |
| `0x80` | `TFL` | TX FIFO 深度/当前级别 | 监控 FIFO |
| `0x84` | `RFL` | RX FIFO 深度/当前级别 | 监控 FIFO |
| `0x88` | `SRR` | 软件复位 | 可分别复位 UART、RX FIFO、TX FIFO |
| `0x9c` | `SRT` | RX FIFO 触发级别 | 控制接收中断水位 |
| `0xa0` | `STET` | TX FIFO empty 触发级别 | 控制发送中断水位 |
| `0xa8` | `DMASA` | DMA 软件应答 | DMA 模式相关 |
| `0xac` 起 | `TCR/DE_EN/RE_EN/DET/TAT` | RS-485 方向和时序 | 普通 TTL UART 不用 |
| `0xc0` | `DLF` | 小数分频值 | K210 使用 4 位小数分频提高波特率精度 |

`LCR` 常用位：

| 位 | 名称 | 含义 |
|---:|---|---|
| `1:0` | `DLS` | `0/1/2/3` 对应 5/6/7/8 数据位 |
| `2` | `STOP` | 0 为 1 个停止位；1 通常为 1.5 或 2 个停止位 |
| `3` | `PEN` | 奇偶校验使能 |
| `4` | `EPS` | 0 奇校验，1 偶校验 |
| `5` | `SP` | stick parity |
| `6` | `BC` | 强制发送 break |
| `7` | `DLAB` | 允许访问 DLL/DLH 分频锁存器 |

`DLAB` 是 UART 初学者最常踩的坑。设置波特率时：

```c
uart->LCR |= 1u << 7;
uart->DLH = dlh;
uart->DLL = dll;
uart->DLF = dlf;
uart->LCR &= ~(1u << 7);
```

若忘记清 DLAB，之后以为自己在向 `THR` 发数据，实际上仍在改 `DLL`；以为在写 `IER`，实际上在改 `DLH`。

本仓库使用 20 位分频量：

```text
divisor = APB0_clock / baud
divisor = (DLH << 12) | (DLL << 4) | DLF
actual_baud = APB0_clock / divisor
```

### 4.4 UART 中断方式

常见中断来源：

- `RDA`：RX FIFO 到达触发阈值；
- `TIMEOUT/CTI`：RX FIFO 中还有少量字节，但一段时间没有新字节；
- `THRE`：TX holding/FIFO 达到可继续发送的状态；
- `LSERR`：overrun、parity、framing 等线路错误。

中断处理应尽量短：把硬件 FIFO 数据搬到软件 ring buffer、更新状态、唤醒等待进程，然后退出。不要在 ISR 中执行会睡眠的操作。

本仓库 `uart_dw_isr()` 读取 `IIR & 0xf` 后分派这些事件。RX/TX 可选择中断或 DMA；DMA 模式下，UART ISR 不应再与 DMA 同时争抢 FIFO。

还要注意本仓库根据 K210 实际行为把 `LSR bit5` 当成 TX busy，`0` 才表示可接受字节。这与常见 16550A 的 THRE 语义不能机械等同，编写移植代码时应以 K210 手册、SDK 和实测为准。

### 4.5 UARTHS 常用寄存器

| 偏移 | 寄存器 | 主要功能 |
|---:|---|---|
| `0x00` | `TXDATA` | bits 7:0 为发送数据；bit31 为 FIFO full |
| `0x04` | `RXDATA` | bits 7:0 为接收数据；bit31 为 FIFO empty |
| `0x08` | `TXCTRL` | TX 使能、停止位、TX watermark |
| `0x0c` | `RXCTRL` | RX 使能、RX watermark |
| `0x10` | `IE` | TX/RX watermark 中断使能 |
| `0x14` | `IP` | TX/RX watermark 中断 pending |
| `0x18` | `DIV` | 波特率分频，通常 `baud = clock / (DIV + 1)` |

轮询发送一个字符：

```c
while (uarths->txdata.full)
  ;
uarths->txdata.data = ch;
```

轮询接收一个字符：

```c
uarths_rxdata_t rx = uarths->rxdata;
if (!rx.empty)
  ch = rx.data;
```

本仓库 K210 控制台初始化为 115200 baud，打开 TX/RX，并通过 watermark 中断驱动软件环形缓冲区。

### 4.6 UART 调试重点

| 现象 | 首先检查 |
|---|---|
| 完全无输出 | TX 引脚 FPIOA、时钟、TX enable、波特率分频、串口工具端口 |
| 输出乱码 | 双方 baud/数据位/校验/停止位、APB 时钟计算、DLAB 是否正确 |
| 不断收到 `0x00` | RX 悬空或被拉低；本仓库为 UART RX 显式打开了上拉 |
| 只能发不能收 | TX/RX 是否接反、RX 中断使能、PLIC、RX FIFO 水位 |
| 少量数据正常，大量丢失 | FIFO 阈值、ISR 延迟、ring buffer 容量、DMA 和 ISR 是否竞争 |
| 最后几个字节不发送 | 过早关闭 TX 中断或只看软件 ring buffer，未等待硬件真正完成 |

## 5. 从零编写一个驱动的推荐步骤

### 第一步：先读三份资料

以 MPU6050 为例，需要同时阅读：

1. K210 技术参考手册的 I2C 章节：了解主控制器寄存器；
2. MPU6050 数据手册/寄存器手册：了解设备地址和设备内部寄存器；
3. 开发板原理图：确认 SDA/SCL 接到哪个 K210 IO、是否已有上拉、电压是否兼容。

少看其中任何一份，都可能出现“软件看起来正确但硬件不工作”。

### 第二步：只做最小轮询版本

先完成：

- 时钟；
- FPIOA；
- 低速率；
- 单设备；
- 单次同步传输；
- 明确超时；
- 明确错误码。

轮询版最容易用逻辑分析仪验证，也最容易把协议问题与中断并发问题分开。

### 第三步：抽象 controller、device、transfer

推荐分层：

```text
板级层
  controller：总线号、DMA 通道、引脚、默认速度
  device：从机地址/CS、SPI mode、最大速度

总线驱动层
  init、configure、transfer、ISR、DMA

设备驱动层
  MPU6050、SSD1306、W25Q64、SD card

设备抽象层
  devsw read/write/ioctl
```

本仓库已经大体采用这种结构：`kernel/board/` 描述板级实例，`kernel/driver/` 操作控制器，`kernel/devsw/` 对上提供文件接口。

### 第四步：加入中断

引入状态对象，例如：

```c
struct transfer_state {
  const uint8 *tx;
  uint8 *rx;
  size_t tx_left;
  size_t rx_left;
  int done;
  int error;
};
```

启动传输时填状态、预填 FIFO、清旧中断、打开必要的 mask。ISR 只做 FIFO 搬运、错误记录和唤醒。线程使用自旋锁与 `sleep/wakeup` 等待，但必须有超时。

### 第五步：加入 DMA

DMA 不是“打开一个寄存器位”就结束，还需：

- 在 SYSCTL 中选择外设 DMA request；
- 分配不冲突的 DMA 通道；
- 配置源/目标地址是否递增；
- 配置传输宽度和 burst size；
- 处理 DMA 完成中断；
- 同时处理外设侧 STOP、BUSY、abort 等状态；
- 考虑缓冲区长度、对齐、生命周期和缓存一致性。

短传输使用 DMA 往往得不偿失，所以本仓库按长度阈值在中断与 DMA 之间选择。

### 第六步：处理并发和错误恢复

至少考虑：

- 两个进程同时访问同一总线；
- ISR 与线程同时修改传输状态；
- 超时后如何屏蔽中断、清 FIFO、复位控制器；
- I2C 从机 NACK 或占住 SDA；
- SPI RX overflow；
- UART ring buffer 满；
- DMA 通道冲突；
- 进程睡眠被信号/kill 打断。

控制器级睡眠锁适合串行化完整事务；自旋锁适合保护 ISR 与等待线程共享的短状态。不要持有自旋锁执行可能睡眠的函数。

## 6. 如何系统阅读寄存器手册

对每个外设按下面顺序建立笔记：

1. 记录基址、IRQ、时钟源、reset 和 FPIOA 功能号；
2. 从“操作流程”章节找出硬件要求的配置顺序；
3. 先圈出 control、enable、status、data、interrupt、FIFO 六类寄存器；
4. 对每个寄存器记录 offset、访问属性、复位值和关键位；
5. 特别标出只允许在 disabled/idle 状态修改的字段；
6. 特别标出 read-to-clear、W1C 和读写别名寄存器；
7. 用一个最小事务把寄存器串起来；
8. 对照官方 SDK 和本仓库代码，看它们为何采用这个顺序；
9. 用逻辑分析仪验证真实波形，不把“寄存器写成功”等同于“总线正确”。

建议给每个寄存器做如下模板：

```text
名称：IC_DATA_CMD
地址：I2C_BASE + 0x10
访问：R/W，读写均有 FIFO 副作用
用途：写 TX 数据/读命令，读 RX 数据
关键位：DAT[7:0]、CMD[8]、STOP[9]、RESTART[10]
前置条件：IC_ENABLE=1，TX FIFO 有空间
完成条件：STOP_DET 或 TX_ABRT
错误路径：读取 TX_ABRT_SOURCE，再清 TX_ABRT
```

## 8. 推荐的学习实验顺序

1. UARTHS 轮询发送字符：只涉及 `DIV`、`TXCTRL`、`TXDATA`；
2. UART1 轮询收发：学习 DLAB、THR/RBR、LSR 和 FPIOA；
3. UART1 中断收发：学习 FIFO、IIR/IER、PLIC 和 ring buffer；
4. I2C 扫描 7 位地址：学习 START、地址 ACK、TX_ABRT；
5. I2C 读取 MPU6050 `WHO_AM_I`：学习 write + repeated START + read；
6. SPI 读取 W25Q64 JEDEC ID：学习 Mode 0、CS、dummy byte 和全双工 FIFO；
7. SPI/UART DMA：最后再学习 DMAC 请求映射、通道和完成同步。

每一步都建议同时保留：寄存器日志、错误状态、逻辑分析仪截图和预期协议时序。这样遇到问题时，能够判断错误位于电气层、协议层、控制器配置层还是操作系统同步层。

## 9. 最后总结

掌握寄存器驱动的关键不是背地址，而是反复使用同一套思路：

```text
找到基址和 offset
  → 打开时钟并配置引脚
  → 在允许的状态下配置控制寄存器
  → 配置 FIFO 和中断/DMA
  → 通过数据寄存器启动事务
  → 用 status/interrupt 判断进度
  → 用专用寄存器清中断并诊断错误
  → 等待总线真正结束
  → 在超时和异常时恢复控制器
```

I2C 的核心是 `DATA_CMD + START/RESTART/STOP + ACK/ABRT`；SPI 的核心是 `CTRLR0 + BAUDR + SER + 双向 FIFO`；UART 的核心是 `DLAB 分频 + LCR 帧格式 + THR/RBR + LSR/IIR`。把这三组核心关系读懂，再学习 DMA、RS-485、Quad SPI 等扩展功能会容易很多。

## 10. 阈值设置（重点）

设计原则与风险：**DMA 的突发传输能力与 FIFO 的水线相匹配，而不是用固定的数值**，RX 水位越高，DMA 请求越少，但 FIFO 溢出的风险越高；TX 水位越高，补充越早，但必须保证剩余空间容纳整个 burst。

不存在一组对所有场景都“最合适”的数值。配置取决于：

- 数据长度是否固定、是否 burst 对齐；
- 更重视吞吐量还是低延迟；
- 是否有 STOP、CTI 等尾部事件；
- CPU/DMAC 中断和响应延迟；
- SPI/I²C 的总线速率。

基本约束如下：

```
TX 请求：TXFLR <= TX_THRESHOLD
需要：TX_THRESHOLD <= FIFO_DEPTH - TX_BURST

RX 请求：RXFLR > RX_THRESHOLD
通常：RX_THRESHOLD = RX_BURST - 1
```

RX 水位越高，DMA 请求越少，但 FIFO 溢出的风险越高；TX 水位越高，补充越早，但必须保证剩余空间容纳整个 burst。

### 推荐默认配置

适合当前 xv6 驱动：实现简单、支持任意长度、可靠性优先。必须把中断水位、外设 DMA 请求水位和 DMAC 的内存 burst 分开记录：

- `TX/RX 中断阈值`：触发外设自身中断的 FIFO 水位；
- `DMA TX/RX 请求阈值`：触发外设 DMA 请求的 FIFO 水位；
- `DMAC TX/RX burst`：DMAC 每次总线事务的传输项数，不是外设 FIFO 水位。

TX 阈值表示“TX FIFO 当前项数小于等于该值时请求补充”。因此，TX 半满不是“发送半满的数据”，而是让 CPU 或 DMA 在 FIFO 还剩一半时提前补充。高速 SPI 适合提前补充；I²C 和 UART 发送速率较低，空 FIFO 触发即可，能够减少中断次数。

按当前驱动实际配置，三者的关系如下：

| 外设 | FIFO | TX/RX 中断阈值 | DMA TX/RX 请求阈值 | DMAC TX/RX burst | 尾部机制 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| I²C | 8项 | `tx_tl=0` / `rx_tl=7` | `dma_tdlr=4` / `dma_rdlr=0` | 4 / 1 | DMA完成后等待 STOP/总线空闲 |
| SPI | 32项 | `txftlr=0` / `rxftlr=0` | `dmatdlr=0` / `dmardlr=0`（当前未显式设置） | 4 / 1 | DMA完成后等待 RX 排空 |
| UART | 8项 | TX 空 FIFO / RX 1字符 | TX 空 FIFO / RX 1字符（`STET=0`、`SRT=ONE_CHAR`） | 1 / 1 | CTI/停止后收割并重启 DMA |

上表是当前代码的实际值，不是最终推荐值。当前 SPI 的 `txftlr` 和 DMA `dmatdlr` 都还没有配置成半满。

其中，I²C 的 `dma_tdlr=4`、`dma_rdlr=0` 和 SPI 的 `dmatdlr`/`dmardlr` 属于外设 DMA 请求阈值，不能用中断阈值列代替。SPI 若要采用“TX 水位 16”的方案，必须在启动 DMA 前显式写入 `dmatdlr=16`，并同时验证 `TX FIFO 剩余空间 >= TX burst`；当前代码并未这样配置，因此表中不能把 16 写成当前值。

这套配置最适合：

- DMA传输长度不一定对齐；
- 希望驱动逻辑简单；
- 优先避免 RX 尾部卡住；
- 尚未实现“DMA主体 + PIO尾部”。

### I²C 配置选择

#### 1. 短消息、寄存器读写

典型长度：1～16 字节。

建议直接用中断或 PIO：

|FIFO|TX中断阈值|RX中断阈值|DMA|
|---|---|---|---|
|8项|0|7|不使用|

原因是启动 DMA、配置通道和等待完成的开销可能高于直接操作 FIFO。

#### 2. 任意长度DMA，可靠性优先

建议保持当前配置：

|FIFO|TX DMA阈值|TX burst|RX DMA阈值|RX burst|
|---|---|---|---|---|
|8项|4|4|0|1|

```
dma_tdlr = 4;
tx_msize = DMAC_MSIZE_4;

dma_rdlr = 0;
rx_msize = DMAC_MSIZE_1;
```

特点：

- TX 一次最多填4项；
- RX 每产生一个结果就能搬走；
- 任意接收长度都不会留下 DMA 尾部；
- RX DMA 请求较多，但 I²C 本身速率不高，一般可以接受。

这是当前 I²C 最合适的默认方案。

#### 3. 长数据且长度4项对齐

可以提高 RX burst：

|FIFO|TX阈值|TX burst|RX阈值|RX burst|
|---|---|---|---|---|
|8项|4|4|3|4|

```
dma_tdlr = 4;
dma_rdlr = 3;
tx_msize = DMAC_MSIZE_4;
rx_msize = DMAC_MSIZE_4;
```

要求：

```
接收项数 % 4 == 0
```

否则最后1～3项达不到 RX 水位，DMA无法完成。

#### 4. 长数据但长度不对齐

可以使用上一组高性能配置，但必须实现：

```
DMA搬运 len / 4 * 4 项
        ↓
STOP_DET
        ↓
停止DMA并收割已完成数据
        ↓
PIO排空最后 len % 4 项
```

在没有实现这套逻辑前，不建议将 I²C RX 改成 burst 4。

### SPI 配置选择

#### 1. 短传输

例如少于16帧，建议使用中断或 PIO：

|FIFO|TX中断阈值|RX中断阈值|DMA|
|---|---|---|---|
|32项|16|0|不使用|

短传输的 DMA 配置开销不划算。

#### 2. 任意长度DMA，可靠性优先

推荐配置（当前代码尚未显式写入 `dmatdlr`，需要实现时补上）：

|FIFO|TX阈值|TX burst|RX阈值|RX burst|
|---|---|---|---|---|
|32项|16|4|0|1|

```
dmatdlr = 16;
tx_msize = DMAC_MSIZE_4;

dmardlr = 0;
rx_msize = DMAC_MSIZE_1;
```

优点：

- RX 每一帧都能触发搬运；
- 不要求帧数是4、8或16的整数倍；
- 不需要处理 SPI RX 尾部；
- RX排空比较积极，降低溢出风险。

这是 SPI 的稳妥 DMA 配置建议，不是当前代码的实际配置；当前代码仍使用 `dmatdlr=0` 的复位默认值。

#### 3. 大块、长度对齐、吞吐优先

可以让 TX/RX 更平衡：

|性能等级|FIFO|TX阈值|TX burst|RX阈值|RX burst|对齐要求|
|---|---|---|---|---|---|---|
|稳健|32|16|4|3|4|4帧|
|平衡|32|16|8|7|8|8帧|
|激进|32|16|16|15|16|16帧|

推荐首先测试平衡方案：

```
dmatdlr = 16;
dmardlr = 7;

tx_msize = DMAC_MSIZE_8;
rx_msize = DMAC_MSIZE_8;
```

它比 burst 16 留有更多 RX FIFO 和 DMA响应余量。

burst 16 虽然满足：

```
FIFO深度 - TX阈值 = 32 - 16 = 16
```

但一次 RX burst 也需要积累16帧，FIFO只剩16帧溢出余量。SPI 时钟较高或 DMAC 仲裁繁忙时，风险更高。

#### 4. 长数据但长度不对齐

有三种选择：

1. 整体使用 `RX burst=1、dmardlr=0`；
2. 不对齐时退回中断/PIO；
3. DMA处理对齐主体，PIO同时发送并接收尾部。

SPI 的 PIO 尾部必须同时处理 TX/RX：

```
写一个尾部TX帧产生时钟
→ 等待RX帧到达
→ 读取RX FIFO
```

不能只在 DMA 结束后读取 RX FIFO，因为没有 TX 就没有 SPI 时钟。

### UART 配置选择

UART 是不定长字符流，通常不知道数据什么时候结束，因此和 I²C/SPI 不同，必须考虑空闲尾部。

#### 1. 交互式终端，低延迟优先

|FIFO|RX水位|RX burst|TX水位|TX burst|
|---|---|---|---|---|
|8项|1字符|1|空FIFO|1|

适用于 shell、命令行等逐字符输入。

优点是字符到达后立即处理；缺点是请求和中断频繁。

#### 2. 通用DMA串口

优化建议（当前代码使用 `SRT=ONE_CHAR`，尚未切换到半满）：

|FIFO|RX水位|RX burst|TX水位|TX burst|尾部|
|---|---|---|---|---|---|
|8项|4字符|1|空FIFO|1|CTI+PIO|

```
SRT = UART_SRT_HALF_FULL;
rx_msize = DMAC_MSIZE_1;

STET = 0;
tx_msize = DMAC_MSIZE_1;
```

工作方式：

```
普通数据：FIFO达到4字符后由DMA搬运
尾部数据：空闲后由CTI中断排空
```

它适合不定长数据流，也适合目前的 UART 烧录协议。

#### 3. 连续大流量UART

可以考虑：

|FIFO|RX水位|RX burst|TX水位|TX burst|尾部|
|---|---|---|---|---|---|
|8项|4字符|4|4字符|4|CTI+PIO|

```
SRT = UART_SRT_HALF_FULL;
rx_msize = DMAC_MSIZE_4;

STET = HALF_FULL;
tx_msize = DMAC_MSIZE_4;
```

优点是显著减少 DMA握手次数。

但 RX 仍然必须保留 CTI 尾部处理，因为发送端停止时可能只留下1～3字符。还需要在硬件上验证 UART DMA请求的持续/撤销行为，确认一次请求能够安全完成4项 burst。

#### 4. 高波特率且系统中断延迟大

建议不要使用接近满 FIFO 的 RX 水位：

|RX水位|建议|
|---|---|
|1字符|最安全，但请求最多|
|半满4字符|吞吐与余量平衡，推荐|
|接近满7字符|不推荐，只有1字符溢出余量|

对于8项 UART FIFO，半满是较合理的上限。

### 最终建议

当前阶段建议使用以下明确分层的配置；其中 SPI 的半满 TX 阈值需要同步写入外设寄存器，不能只改表格：

| 外设 | FIFO | TX/RX 中断阈值 | DMA TX/RX 请求阈值 | DMAC TX/RX burst | 原因 |
| --- | --- | --- | --- | --- | --- |
| I²C | 8项 | 0 / 7 | 4 / 0 | 4 / 1 | I²C较慢，TX 保留4项空间，RX用单项请求收尾 |
| SPI | 32项 | 16 / 0 | 16 / 0 | 4 / 1 | TX提前补充，RX单项搬运，支持任意长度 |
| UART | 8项 | 空FIFO / 半满 | `STET=0` / `SRT=HALF_FULL` | 1 / 1 | RX保留4项余量，CTI负责1～3字符尾部 |

如果以后做性能优化，建议按以下顺序推进：

1. 先测量 DMA请求次数、FIFO溢出和传输耗时。
2. SPI 将 RX burst 从1提高到4，并增加长度对齐或尾部处理。
3. I²C 只有在长消息占比很高时才提高 RX burst。
4. UART 保留半满水位和 CTI，必要时再把 TX/RX burst 提高到4。

核心原则是：TX 可以积极使用较大 burst；RX 必须先解决尾部和溢出问题，再增大 burst。

I²C/UART 保持较低 TX 阈值，主要是为了减少无意义的中断。若追求统一的高吞吐策略，也可以把 I²C 的 tx_tl 改成 4，但对 I²C 实际收益通常不大。
