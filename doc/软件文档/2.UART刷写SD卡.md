# UART 刷写 SD 卡

本文记录在 xv6-k210 中实现通过 UART 将主机端 `target/fs.img` 写入 SD 卡的开发和调试过程。传输分两个 baud 阶段：先用 115200 baud 完成 shell/INFO 握手，握手通过后再切换波特率进入数据阶段。主机 baud 与板端 baud 现在是同一个参数（`--baud`，不再有 11/10 补偿），切换细节见下文「波特率切换」一节。数据阶段可以选择走 console（UARTHS）单口，也可以切到独立的 DW UART1（`/dev/ttyS0`，DMA）双口数据通路（`--data-port`）；`make download` 默认就是双口 + `DOWNLOAD_BAUD`（默认 1500000）。数据阶段使用分包 CRC32 校验、逐扇区 ACK/NAK。主机端会解析 FAT32，只发送实际已分配区域，而不是固定发送整个 64MiB 镜像。

## 目标

原始更新 SD 卡文件系统需要读卡器写入：

```sh
make sdcard dev-sd=/dev/sdX
```

目标是板子启动后在 shell 中运行用户程序 `burn`，主机运行：

```sh
python3 tools/burn.py /dev/ttyUSB0 target/fs.img
```

通过 UART 将 `fs.img` 写到 SD 卡起始扇区，从而更新板上 FAT32 文件系统。

## 涉及文件

- `user/app/burn.c`
  板端烧写程序，接收 UART 包、校验 CRC、写 SD 卡、回 ACK/NAK。

- `tools/burn.py`
  主机端发送脚本，启动板端 `burn`，发送 INFO/DATA/DONE 包，处理 ACK/NAK 和重试。

- `kernel/devsw/console.c` / `kernel/include/console.h`
  console 设备层，在同一个 `DEV_CONSOLE` 上提供 TTY/RAW 模式、波特率设置和 RX 统计 ioctl。

- `kernel/driver/uarths.c` / `kernel/include/uarths.h`
  UARTHS 字节流驱动，统一管理 RX/TX ring buffer、中断、硬件 FIFO 和波特率，服务 `/dev/console`。

- `kernel/driver/uart.c` / `kernel/include/uart.h` / `kernel/driver/ringbuffer.c`
  DW UART1 字节流驱动（PIO/DMA 双模式，RX DMA CH5 / TX DMA CH4）和共用的环形缓冲抽象。数据阶段双口模式（`--data-port`）由它承担。

- `kernel/devsw/uartdev.c`
  `/dev/ttyS0` 字符设备，RAW 字节流 + `UART_IOCTL_SET_MODE`，ioctl 命令号与 console 对齐。

- `kernel/devsw/sdcarddev.c`
  SD 卡字符设备，提供按 512 字节扇区读写的接口，并在直接写盘后提供文件系统缓存失效 ioctl。

- `kernel/fs/bio.c` / `kernel/fs/fat32.c`
  FAT32 文件系统和块缓存。UART 刷写直接写 SD 扇区，绕过这两层，因此刷写完成后必须失效缓存，避免连续刷写时 exec 读到旧缓存。

- `user/libc/oled.c` / `user/include/oled.h`
  OLED 用户态驱动，用于烧写过程中的简要状态显示。

- `Makefile`
  生成 `fs.img`，烧写内核，读卡器写入/校验 SD 卡。

## 当前协议

主机和板端通过带 CRC32 的二进制帧通信。

帧格式：

```text
magic(4) = 55 AA 55 AA
seq(4 LE)
type(1)
plen(2 LE)
payload(plen)
crc32(4 LE)
```

CRC32 覆盖 `magic` 到 `payload` 的所有字节，使用与 Python `zlib.crc32()` 兼容的 reflected polynomial `0xEDB88320`。

包类型：

```text
PKT_INFO = 0x01  主机 -> 板端，payload 为镜像大小(4) + 目标 baud(4) + data_port(1，可选)
PKT_DATA = 0x02  主机 -> 板端，payload 为 512 字节扇区
PKT_DONE = 0x03  主机 -> 板端，表示传输完成
PKT_BAUD = 0x04  主机 -> 板端，baud 切换请求/同步，payload 为 4 字节目标 baud（LE，即 --baud）
PKT_ACK  = 0x81  板端 -> 主机，表示接受
PKT_NAK  = 0x82  板端 -> 主机，表示拒绝，payload 为错误码
```

ACK payload 当前包含诊断信息：

```text
reason(1)
ticks(4 LE)
```

`reason` 的含义：

```text
OK   正常写入并 ACK
DUP  收到已经写过的旧 DATA，重发 ACK，不重复写 SD
INFO INFO 阶段 ACK
DONE DONE 阶段 ACK
BAUD baud 切换阶段 ACK
```

`ticks` 在 `OK` 时表示一次 `write(sdcard_fd, ..., 512)` 花费的 `uptime()` tick 数；在 `BAUD` 时，READY ACK 携带板端目标 baud，同步 ACK 携带切换后实际 baud（`freq/(div+1)`）。

## 板端流程

`user/app/burn.c` 的主要流程：

1. 打开 `DEV_CONSOLE` 和 `DEV_SDCARD`；协议设备 `uart_fd` 初始指向 console。
2. 初始化 OLED。
3. `CONSOLE_IOCTL_SET_MODE(CONSOLE_MODE_RAW)` 将 console 切换到 RAW 模式。
4. 发送 `BURN\n` 给主机。
5. 接收 INFO：payload 第 1~4 字节镜像大小（计算扇区数）、第 5~8 字节
   `--baud`（非法值回退 115200）、第 9 字节数据口选择 `data_port`。
6. 若 `data_port == 1`：打开 `/dev/ttyS0`，把 UART1 线速复位到 115200（清除
   上次崩溃残留的分频值）、设 RX/TX 为 DMA 模式、清空 RX 残留，`uart_fd`
   切到 uart1；之后 ACK/BAUD/DATA/DONE 全走 uart_fd。
7. 检查 SD 卡容量，`SDCARD_IOCTL_SEEK` 到 0 扇区。
8. 波特率切换（可选）：若 `--baud` 非 115200，先在 115200 下接收 BAUD 请求，
   回 BAUD READY ACK（ticks = 目标 baud），再调用 `CONSOLE_IOCTL_SET_BAUD`
   切到 `--baud`；随后在新 baud 下接收 BAUD 同步包，回 ACK（ticks = 实际
   baud `freq/(div+1)`）。
9. 逐扇区接收 DATA：
   - CRC 错误：回 NAK。
   - `seq < sec`：说明主机没收到旧 ACK，重发 ACK，不重复写。
   - `seq != sec` 或长度错误：回 NAK。
   - 正常：写 SD 卡，然后回 ACK。
10. 接收 DONE，回 ACK，失效 FAT/buffer cache。
11. 收尾（`finish:`）：若切过波特率，先对 `uart_fd` 恢复 115200；读 RX 统计；
    对 `uart_fd` 调 `SET_MODE(TTY)`（uart1 会拒绝并忽略，console 恢复 TTY）；
    双口模式下再单独把 console 恢复 TTY，然后 printf 收尾日志。

关键约束：

正常数据热路径中不要刷新 OLED，也不要 `printf()`。UART RX FIFO 很小，OLED
I2C 刷屏和 console 输出都可能让下一包数据溢出。双口模式下 DATA 走 uart1，
console 变成空闲旁路，可以在错误分支往 console `printf` 诊断而不会干扰帧流
（`uart_fd != console_fd` 的分支）。

## 主机端流程

`tools/burn.py` 的主要流程：

1. 打开 console 串口 @ 115200 用于 shell 握手；若 `--data-port`，同时打开数据口
   @ 115200 并清空两个口的缓冲（协议设备 `proto` 指向数据口，否则指向 console）。
2. 发送 `/burn\n`，等待板端 `BURN\n`。如果路径执行失败，自动尝试 `burn`、`/bin/burn`、`bin/burn`。
3. 在 console 上发送 INFO 包，payload 为 `fs.img` 大小、`--baud` 和数据口选择
   （`1 if --data-port else 0`）。
4. 从 `proto`（数据口）等待 INFO ACK。双口模式下若等不到，多半是 SD 里的
   `/burn` 是旧版（不认 data_port），会提示先单口 `make download` 更新一次。
5. 如果 `--baud` 不是 115200：在 `proto` 上以 115200 发送 BAUD 请求，收到
   BAUD READY 后把 `proto` 切到 `--baud`，再在新 baud 下发送 BAUD 同步包
   （最多重试 3 次），直到收到携带实际 baud 的 BAUD ACK。同步失败会中止，
   提示回退到 `--baud 230400`。
6. 解析 FAT32 的 FAT 表，裁剪到最后一个已分配 cluster，只发送有效区域。
7. 按 512 字节切分待发送数据。
8. 每个扇区发送 DATA，等待 ACK/NAK。
9. ACK 的 `seq` 必须等于当前扇区，否则视为旧响应。
10. 超时或 CRC 错误时重试。
11. 最后发送 DONE，并把数据口切回 115200，从 console 读取板端恢复 TTY 模式后
    打印的收尾日志。

逐包日志默认关闭，只在重试/错误时打印。需要全量详细日志时使用 `--verbose`：

```text
sec=0 attempt=1: send DATA len=512
sec=0 attempt=1: recv ACK seq=0 reason=OK ticks=0
```

```sh
python3 tools/burn.py --verbose --baud 500000 /dev/ttyUSB0 target/fs.img
```

## 波特率切换

### 为什么需要切换波特率

shell 启动、`/burn` exec 和 INFO 握手都在 115200 baud 下进行，低 baud 下交互最稳定。但有效镜像有几 MB，纯 115200 传输太慢，所以握手确认后再切到更高 baud 发送 DATA。

切换必须保证双方几乎同时处在同一个速率，否则会出现"主机已切走、板端还在旧速率"或相反的窗口，字节流整体错乱。因此协议用两步握手：先在旧 baud 下确认"准备切换"，再在新 baud 下确认"同步成功"，之后才进入 DATA 阶段。

### 主机 baud 与板端 baud 同速

K210 UARTHS 的波特率由 CPU 时钟整数分频决定：`actual = freq / (div + 1)`，`freq` 是 CPU 时钟频率，`div` 是 16 位分频值。它只能近似某个请求值，不能像主机 USB 转串口芯片那样精确到任意 baud。

命令行只暴露 `--baud` 一个参数，主机与板端使用同一个速率：`ser.baudrate` 与 INFO payload 第 5~8 字节发给板端（`CONSOLE_IOCTL_SET_BAUD` 的目标值）相同，不做任何补偿。`--baud` 设 115200 即为最保守组合。

### 完整时序

主机与板端同速（都是 `--baud`）：

1. 主机在 115200 下发送 `PKT_BAUD`，payload = `--baud`（主机与板端相同的目标速率）。
2. 板端回 `ACK_BAUD`（READY，ticks = 目标 baud）。
3. 板端调用 `CONSOLE_IOCTL_SET_BAUD` 切到 `--baud`。该 ioctl 会先等 TX 数据和硬件 FIFO 排空、暂停 RX 中断并清空硬件 FIFO，再改 `div`，最后恢复 RX 中断。
4. 主机收到 READY 后，把自己的串口切到 `--baud`，清空输入缓冲。
5. 主机在新 baud 下再发一次 `PKT_BAUD` 作为同步包（最多重试 3 次）。
6. 板端在新 baud 下收到同步包，回 `ACK_BAUD`，ticks = 实际 baud `freq/(div+1)`。
7. 主机收到同步 ACK，进入 DATA 阶段。

双口模式下整个时序发生的位置不同：INFO ACK 之后板端已经把协议设备切到
`/dev/ttyS0`，因此上面的 `PKT_BAUD` 请求/READY/同步/ACK 全部在 UART1 上
进行（同样从 115200 开始），主机把 `--data-port` 打开的那个串口切到
`--baud`；console 口始终停在 115200，只跑 shell 握手和收尾日志。

如果第 5 步连续 3 次都收不到同步 ACK，说明新 baud 组合下双方无法互通，
`burn.py` 会中止，提示回退到已验证的 `--baud 230400`。这时需要复位板子
重新开始。

DONE 阶段结束（或中途失败）后，板端若切过波特率，会先 `CONSOLE_IOCTL_SET_BAUD`
恢复 115200，再读 RX 统计、恢复 TTY 模式并打印收尾日志；主机随后也切回
115200 读取这段 console tail。单口模式下这段 tail 就在数据串口上，双口模式下
在 console 口上。

## UART 与 console 分层设计

UARTHS/Console 分层重构时，旧的 UARTHS 专用 `uartdev.c`、`DEV_UART` 和
`UART_IOCTL_*` 已删除，普通终端只打开 `DEV_CONSOLE`：UARTHS 驱动负责稳定的
字节收发，console 设备层负责 TTY/RAW 语义和 ioctl。

高速烧写提速后新增了 **DW UART1** 驱动（`kernel/driver/uart.c`）和新的
`kernel/devsw/uartdev.c`，以 `/dev/ttyS0`（`DEV_UART1`）暴露 RAW 字节流设备，
支持 `UART_IOCTL_SET_MODE` 在 PIO/DMA 之间统一切换收发路径。
`burn.c` 收到 INFO 中 `data_port=1` 时打开 `/dev/ttyS0` 作为数据通路，shell
握手和收尾日志仍在 console。ioctl 命令号与 `CONSOLE_IOCTL_*` 对齐，因此切换
数据设备时协议逻辑不变。

当前 console ioctl 如下：

- `CONSOLE_IOCTL_FLUSH_INPUT`：清空硬件 FIFO 和统一 RX ring，并重置 TTY 解析状态。
- `CONSOLE_IOCTL_SET_MODE`：设置 `CONSOLE_MODE_TTY` 或 `CONSOLE_MODE_RAW`。模式切换期间暂停 RX 中断并清空输入，防止边界字节被旧模式解析。
- `CONSOLE_IOCTL_GET_MODE`：返回当前 TTY/RAW 模式。
- `CONSOLE_IOCTL_SET_BAUD`：等待 TX 数据和硬件 FIFO 发送完成后设置 baud，用于数据阶段加速及退出前恢复 115200。
- `CONSOLE_IOCTL_GET_BAUD_INFO`：查询 requested、actual、div 和 clock。
- `CONSOLE_IOCTL_GET_RX_STATS`：查询统一 RX ring 的 dropped、buffered、capacity、当前 mode 和硬件 overrun（UARTHS 无 overflow 位，恒 0）。
- `CONSOLE_IOCTL_SET_FG_PGRP`/`GET_FG_PGRP`：管理前台进程组，供 shell 的作业控制和 Ctrl-C（SIGINT）使用。

`/dev/ttyS0` 的 ioctl 命令号与上面 `CONSOLE_IOCTL_*` 对齐（`SET_MODE` 只接受
RAW），另外增加 `UART_IOCTL_SET_MODE` 统一选择 PIO/DMA 通路；其
`GET_RX_STATS` 的 `info[3]` 是当前模式、`info[4]` 是
DW UART1 真实的 LSR OE overrun 计数。

`burn.c` 在切换 RAW 模式后，通过同一个 console fd（或双口模式下的
`/dev/ttyS0` fd）读写二进制协议。`read()` 从 UART RX ring 阻塞取数据，
`write()` 把整块数据写入 TX ring，由 TX 中断继续排空，不再逐字节调用
`uarthsputc_sync()`。`burn.c` 会循环调用 `read()`，直到读满协议帧需要的字节数。

UART RX 中断不再根据 console 模式分流，而是始终将硬件 FIFO 搬入唯一的 RX
ring。TTY 字符处理被上移到 `consoleread()`：TTY 模式负责 CR/LF 归一化、回显、
`Ctrl-P`、`Ctrl-D`、Ctrl-C（SIGINT）和 ANSI 转义序列；RAW 模式则直接返回未
解析字节。

重构后的数据路径（console/UARTHS）：

```text
UART RX interrupt
  -> uarthsintr()
  -> unified RX ring (32768 bytes)
  -> uarths_read()
  -> consoleread()
       TTY mode: CR/LF, echo, control/escape handling
       RAW mode: copy bytes unchanged
  -> read(console_fd, ...)

write(console_fd, ...)
  -> consolewrite()
  -> uarths_write()
  -> TX ring (4096 bytes)
  -> uarths_tx_service() / UART TX interrupt
  -> hardware TX FIFO
```

双口模式下 DATA 阶段的路径换成 DW UART1（`kernel/driver/uart.c`）：RX DMA
CH5 块（512B）或 CTI 收割进 ring，TX DMA CH4 块（256B）直接搬 FIFO，不再走
console 的 TTY 处理。

RX ring 有效容量为 32767 字节，能容忍短时间调度、SD 写入和系统调用开销造成的延迟。ring 满时丢弃新字节并累加 dropped 计数。`burn` 在结束或失败时通过 `CONSOLE_IOCTL_GET_RX_STATS` 取得统计；日志中为了兼容旧的测试数据，字段名仍保留为 `raw_drop` 和 `raw_buf`，实际表示统一 RX ring。

重构保留了中断接收并进一步去掉了 UART 驱动中的 console 依赖。timer interrupt 可正常调度，UART 接收不依赖用户态进程持续运行，也不需要独立 raw ring 或 `no_preempt`。

## OLED 调试过程

最初 `burn.c` 中有多个本地 wrapper：

```c
dbg_status()
dbg_info()
dbg_line2()
dbg_hexrow()
```

后来将 OLED 驱动改成全局状态，`oled_init()` 返回成功/失败，不再向调用者暴露 I2C fd。常用接口变为：

```c
oled_write_row(row, str);
oled_printf(row, col, fmt, ...);
oled_show_hex32(row, col, value);
oled_write_hexrow(row, label, data, n);
```

同时把十六进制行显示逻辑下沉到 OLED 库中，`burn.c` 不再自己拼 16 字符缓冲。

调试中曾加入 `GOT DATA`、`SD WRITE`、`SEND ACK` 等细粒度 OLED 状态。但这些状态位于数据热路径，I2C 刷屏会干扰 UART 接收，导致 ACK 超时。因此最终稳定版只保留阶段/错误显示；正常数据阶段约每完成 5% 刷新一次进度。

当前进度显示：

```text
WRITING FS V2
SEC 1280
TOT 5252
PROGRESS 24%
```

这里 `SEC` 和 `TOT` 都是十进制。调试过程中曾出现：

```text
SEC 12801546
PROGRESS 16%B
```

根因是 `oled_printf()` 只覆盖新字符串，不清空整行；上一帧残留的 `1546` 或 `B` 留在行尾。修复方式是进度显示先 `snprintf()` 到 16 字符缓冲，再调用 `oled_write_row()` 整行清空并写入。

另一个显示问题是用户态 `printf/vsnprintf` 原本不支持 `%u`，导致 `SEC/TOT/PROGRESS` 格式显示异常。修复是在 `user/printf.c` 的格式化分支中增加 `%u`，因此 `printf`、`snprintf`、`oled_printf` 都可以输出无符号十进制。

## SD 卡内容验证

读卡器写入：

```sh
make sdcard dev-sd=/dev/sdX
```

验证 SD 卡内容：

```sh
make verify-sd dev-sd=/dev/sdX
```

该目标会：

1. 检查 `dev-sd` 是否能被 `lsblk` 识别。
2. 读取 sector 0 offset 82 的 FAT32 签名。
3. 用 `cmp -n` 比较 `target/fs.img` 和 SD 卡起始区域。

如果完全一致，会输出：

```text
SD content matches target/fs.img
```

## 当前稳定用法

生成 64MiB 文件系统：

```sh
make fs
```

第一次或 SD 卡损坏时，用读卡器写入：

```sh
make sdcard dev-sd=/dev/sdX
make verify-sd dev-sd=/dev/sdX
```

板子能进入 shell 后，可以通过 UART 更新。最常用的是 Makefile 目标 `make download`，
默认走双口高速档：

```sh
make download        # 等价于 burn.py --baud 1500000 --data-port /dev/ttyUSB0 /dev/ttyUSB1
```

`DOWNLOAD_BAUD`（默认 1500000）和 `DATA_PORT`（默认 /dev/ttyUSB0，传给
`--data-port`）/ `CONSOLE_PORT`（默认 /dev/ttyUSB1）都可在命令行覆盖：
`make download DOWNLOAD_BAUD=500000 DATA_PORT=` 会退回单 console 口。

手动调用时，单口（数据阶段与握手共用 console）：

```sh
python3 tools/burn.py --baud 500000 /dev/ttyUSB1 target/fs.img
```

双口（数据阶段走 `/dev/ttyS0` DMA，握手在 console）：

```sh
python3 tools/burn.py --baud 1500000 --data-port /dev/ttyUSB0 /dev/ttyUSB1 target/fs.img
```

`--baud` 默认 230400；主机与板端同速，无补偿。保守场景可用 `--baud 230400`，
稳定高速档单口用 `--baud 500000`、双口用 `--baud 1500000`。双口模式要求 SD
里的 `/burn` 是新版（支持 INFO 的 data_port 字节），否则板端会在 console 上回
ACK，主机在数据口等不到，报错提示先单口 `make download` 更新一次。

如果当前板子根目录 `/burn` 不可执行，但 `/bin/burn` 可执行，可以指定：

```sh
python3 tools/burn.py --burn-cmd /bin/burn --baud 500000 /dev/ttyUSB0 target/fs.img
```

详细日志：

```sh
python3 tools/burn.py --verbose --baud 500000 /dev/ttyUSB0 target/fs.img
```

只检查将要发送多少数据，不打开串口：

```sh
python3 tools/burn.py --dry-run --baud 500000 /dev/ttyUSB0 target/fs.img
```

刷写成功后，如果看到：

```text
Board console tail:
burn: done sectors=... bytes=... cache=0
```

说明新版 kernel 已完成 FAT/buffer cache 失效，可以继续不重启刷下一次。

`make run platform=k210` 只烧 kernel，不写 SD 文件系统。更新了 kernel 之后仍需要再执行 UART burn 或读卡器写 SD。Makefile 现在会打印提示：

```text
K210 kernel flashed. SD filesystem is not updated by make run.
Use 'make sdcard dev-sd=/dev/XXX' or 'python3 tools/burn.py /dev/ttyUSB0 target/fs.img' to update fs.img.
```

## 后续优化方向

### 1. 多扇区窗口

当前是 stop-and-wait：每个 512 字节 DATA 等一个 ACK。吞吐受 RTT 和 SD 写入影响。后续可以考虑一次发送多个扇区，再统一 ACK bitmap，但实现复杂度会明显增加。

### 2. SD 多块写入

当前每扇区调用一次 `sdcard_write_sector()`。可考虑 SD 多块写命令提升写入效率，但需要改 SD 驱动，并处理失败回滚/重试策略。

### 3. 构建系统与镜像内容一致性

当前 `tools/mkfs.py` 会递归扫描 `build/user/**/_*`，因此旧的构建产物即使不在 `UPROGS` 中，也可能被写入 `fs.img`。调试中就出现过源文件已删除，但对应的旧 `_uartbaud` 构建产物仍被打进镜像的情况。

后续可以把 `mkfs.py` 改为读取 Makefile 导出的用户程序清单，或在 `make fs` 前清理不在 `UPROGS` 的旧 `_` 程序，避免镜像内容和 Makefile 预期不一致。

## 流程总结
**总结流程**：
```text
┌──────────────────────────────┐        ┌──────────────────────────────┐
│              PC              │        │          K210 / xv6          │
│          tools/burn.py        │        │           user/burn          │
└───────────────┬──────────────┘        └───────────────┬──────────────┘
                │                                       │
                │  1. 发送 /burn @115200                │
                │     （console）                        │
                ├──────────────────────────────────────►│
                │                                       │ shell exec /burn
                │                                       │ 打开 console/SD/OLED
                │                                       │ console 切到 RAW
                │                                       │
                │  2. BURN（console）                    │
                │◄──────────────────────────────────────┤
                │                                       │
                │  3. INFO(image_size, --baud,          │
                │      data_port) （console）           │
                ├──────────────────────────────────────►│
                │                                       │ data_port=1：
                │                                       │   打开 /dev/ttyS0
                │                                       │ 检查 SD 容量
                │                                       │ seek 到 sector 0
                │
                │  4. ACK INFO（数据口）                 │
                │◄──────────────────────────────────────┤
                │                                       │
                │  5. BAUD request @115200（数据口）     │
                ├──────────────────────────────────────►│
                │                                       │ 准备切换 baud
                │
                │  6. BAUD READY                        │
                │◄──────────────────────────────────────┤
                │ 切到 --baud                           │ 切到 --baud
                │                                       │
                │  7. BAUD sync @--baud                 │
                ├──────────────────────────────────────►│
                │                                       │
                │  8. BAUD ACK                          │
                │◄──────────────────────────────────────┤
                │                                       │
                │  9. DATA(seq, 512B, CRC32) @--baud    │
                ├──────────────────────────────────────►│
                │                                       │ 校验 CRC
                │                                       │ 写 SD sector
                │
                │ 10. ACK / NAK                         │
                │◄──────────────────────────────────────┤
                │                                       │
                │        重复 DATA 直到所有扇区完成      │
                │                                       │
                │ 11. DONE                              │
                ├──────────────────────────────────────►│
                │                                       │ 恢复 115200
                │                                       │ 清 FAT/buffer cache
                │
                │ 12. ACK DONE                          │
                │◄──────────────────────────────────────┤
                │                                       │
                │ 13. console tail（console）           │
                │◄──────────────────────────────────────┤
                │    burn: done ... cache=0             │
                │                                       │
┌───────────────▼──────────────┐        ┌───────────────▼──────────────┐
│        主机显示 100%          │        │      OLED 显示 BURN SUCCESS   │
└──────────────────────────────┘        └──────────────────────────────┘
```

图中「数据口」指：默认（`data_port=0`）数据口就是 console（UARTHS），步骤 3 之后
全部在该口进行；`--data-port`（`data_port=1`）时，板端收到 INFO 后打开
`/dev/ttyS0`，步骤 4 起的 ACK/BAUD/DATA/DONE 全部走 UART1（DMA），console
只在步骤 1-2 的握手和步骤 13 的收尾日志出现。两种模式下主机与板端波特率相同
（都是 `--baud`）。

**详细流程**：
```text
主机 PC                                  K210 / xv6 板端
────────────────────────────────────────────────────────────────

准备阶段
  make fs
    │
    ├─ 编译 user/_burn
    ├─ 创建 target/fs.img
    └─ 写入用户程序到 FAT32
          ├─ /burn
          └─ /bin/burn


启动板端 burn
  python3 tools/burn.py [--data-port <uart1_port>] ...
    │
    ├─ 打开 console /dev/ttyUSB1 @ 115200
    ├─ 若 --data-port：同时打开数据口 /dev/ttyUSB0 @ 115200
    │     并清空两个口的输入缓冲
    │
    ├─ 发送 shell 命令（console）
    │     /burn
    │     如果失败，尝试 burn / /bin/burn / bin/burn
    │
    │───────────────────────────────▶ shell exec burn
                                      │
                                      ├─ 打开 DEV_CONSOLE
                                      ├─ 打开 DEV_SDCARD
                                      ├─ 初始化 OLED
                                      ├─ CONSOLE_IOCTL_SET_MODE(RAW)
                                      └─ 发送 "BURN\n"
    │◀───────────────────────────────│
    │
    └─ 收到 BURN，确认板端 console 已进入 RAW 模式


INFO 阶段
  解析 target/fs.img
    │
    ├─ 读取 FAT32 BPB
    ├─ 扫描 FAT 表
    ├─ 找到最后一个已分配 cluster
    └─ 只发送有效区域，不发送 64MiB 尾部空闲区
    │
    ├─ 发送 INFO（console）
    │     payload = image_size + --baud + data_port(0/1)
    │───────────────────────────────▶ 接收 INFO（console）
                                      │
                                      ├─ 计算 nsectors
                                      ├─ 检查 SD 容量
                                      ├─ SDCARD_IOCTL_SEEK 到 0
                                      ├─ data_port=1：打开 /dev/ttyS0
                                      │     复位到 115200、清 RX 残留
                                      └─ ACK INFO（数据口）
    │◀───────────────────────────────│
    │
    └─ INFO ACK 在数据口读到（单口 = console，双口 = uart1）


波特率切换阶段（发生在数据口，单口 = console，双口 = uart1）
  当前数据口 baud = 115200
    │
    ├─ 发送 BAUD request（payload = --baud）
    │───────────────────────────────▶ 收到 BAUD request
                                      │
                                      ├─ ACK BAUD READY
                                      ├─ 等待 TX 空闲
                                      └─ CONSOLE_IOCTL_SET_BAUD 到 --baud
    │◀───────────────────────────────│
    │
    ├─ 主机把数据口切到 --baud，清输入缓冲
    │
    ├─ 发送 BAUD sync
    │───────────────────────────────▶ 新 baud 下收到 BAUD sync
                                      │
                                      └─ ACK BAUD actual
    │◀───────────────────────────────│
    │
    └─ 进入数据传输阶段（数据口 @ --baud）


DATA 阶段
  for sec in 0..nsectors-1
    │
    ├─ 读取 512 字节
    ├─ 封包 DATA(seq=sec, crc32)
    │───────────────────────────────▶ recv_msg()
                                      │
                                      ├─ 找 magic 55 AA 55 AA
                                      ├─ 读 header / payload / crc
                                      ├─ CRC 错误：NAK CRC
                                      ├─ 帧中断流：NAK TRUNCATED
                                      ├─ 非法包结构：NAK PROTOCOL
                                      ├─ 读取失败：NAK IO
                                      ├─ seq 旧包：ACK DUP
                                      ├─ seq 不匹配：NAK PROTOCOL
                                      └─ 正常：
                                            write(sdcard_fd, sector, 512)
                                            ACK OK
    │◀───────────────────────────────│
    │
    ├─ ACK：进入下一扇区
    ├─ NAK/timeout：重试，最多 MAX_RETRY
    └─ 主机显示进度 Sector x/y

  OLED 约每完成 5% 刷新一次：
    WRITING FS V2
    SEC 当前扇区
    TOT 总扇区
    PROGRESS 百分比


DONE 阶段
  所有 DATA ACK 后
    │
    ├─ 发送 DONE（数据口）
    │───────────────────────────────▶ 收到 DONE（数据口）
                                      │
                                      ├─ ACK DONE（数据口）
                                      ├─ CONSOLE_IOCTL_SET_BAUD 恢复 115200
                                      │     （作用于数据口）
                                      ├─ SDCARD_IOCTL_INVALIDATE_CACHE
                                      │     ├─ fat32_invalidate()
                                      │     └─ binvalidate(0)
                                      ├─ CONSOLE_IOCTL_GET_RX_STATS
                                      ├─ CONSOLE_IOCTL_SET_MODE(TTY)
                                      │     （作用于 console）
                                      ├─ OLED 显示 BURN SUCCESS
                                      └─ printf（console）:
                                           burn: done sectors=... bytes=... cache=0
    │◀───────────────────────────────│
    │
    ├─ 主机切回 115200
    ├─ 读取 console tail（双口模式下从 console 读，单口就是从数据口读）
    └─ 打印：
        Transfer completed successfully
        burn: done ... cache=0
```
