# 用户代码优化

## Shell 交互优化

本次用户态优化主要集中在 `user/sh/sh.c`。目标是让 xv6 的 shell 更接近实机串口环境下可用的交互终端：支持逐字符输入、退格、整行清除、Tab 补全、上键历史命令，并避免前台程序运行期间输入的空行在程序结束后反复触发提示符。

### 改动概览

`user/sh/sh.c` 的 `getcmd()` 从原来的 `gets()` 改为逐字符读取：

- `\n`：确认当前命令行。
- `0x04`：`Ctrl-D`，空行时作为 EOF。
- `0x15`：`Ctrl-U`，清除当前输入行。
- `0x7f` 或 `\b`：退格删除一个字符。
- `\t`：触发当前目录下的文件名补全。
- `ESC [ A` / `ESC O A`：识别上键，载入上一条非空命令。
- `[A`：兼容部分串口工具丢失 ESC 前缀时的上键输入。

配套改动包括：

- 新增 `history[100]` 保存最近一条非空命令。
- 新增 `erase_line()` 统一清理当前输入行及屏幕显示。
- 新增 `load_history()` 在上键触发时擦掉当前输入并显示历史命令。
- 新增 `save_history()` 在命令执行前保存上一条非空命令。
- 前台命令结束后调用 `ioctl(0, CONSOLE_IOCTL_FLUSH_INPUT, 0)`，丢弃程序运行期间用户敲下的空行或残留输入。

### 设计背景

原始 shell 依赖 `gets()` 获取一整行输入，只有按下回车后用户态才能拿到缓冲区内容。这种方式无法支持 Tab 补全和上键历史，因为这两类功能都要求 shell 在按键发生时立即响应。

因此输入路径被调整为：

1. 内核 console 工作在非规范模式，按字符唤醒读取者。
2. console 只负责基础输入输出，不在内核中做文件名补全或命令历史。
3. shell 逐字符读取并维护用户态行编辑状态。

这样职责边界更清晰：内核提供原始字符流，shell 决定这些字符如何影响命令行。

### Tab 补全

`complete_word()` 负责补全当前光标前的最后一个单词：

1. 从输入缓冲区中向前查找空格，确定当前词前缀。
2. `open(".", 0)` 打开当前目录。
3. 通过 `readdir()` 枚举目录项。
4. 跳过 `.` 和 `..`。
5. 使用前缀匹配收集候选项。
6. 如果只有一个匹配项，擦掉旧前缀并写入完整文件名。
7. 如果存在多个匹配项，换行列出候选项，再重绘 `$ ` 和当前输入。

边界处理：

- 当前词为空时不补全，避免一次性列出全部目录项。
- 补全后不自动追加空格，用户可以继续输入路径或参数。
- 多匹配时不修改输入缓冲区，只刷新显示。

### 上键历史命令

shell 保存最近一条非空命令。用户按上键时，`getcmd()` 识别 ANSI 转义序列并调用 `load_history()`：

- `ESC [ A`：常见终端上键序列。
- `ESC O A`：部分终端模式下的上键序列。
- `[A`：K210 串口调试场景中，某些工具可能丢失 ESC 前缀，因此保留降级兼容。

加载历史命令时，shell 会先用 `erase_line()` 清掉当前输入，再把历史命令拷贝到输入缓冲区并显示出来。

### 前台程序输入清理

在运行 `ls`、`iotest`、`cpuburn` 等前台程序时，用户可能会连续按回车。由于 console 是逐字符输入，这些按键会先进入输入缓冲区。如果不处理，前台程序退出后 shell 会立刻读到这些残留换行，表现为连续出现多个 `$`。

为解决这个问题，shell 在 `wait(0)` 返回后调用：

```c
ioctl(0, CONSOLE_IOCTL_FLUSH_INPUT, 0);
```

该 ioctl 由 `kernel/devsw/console.c` 实现，作用是丢弃 console 中尚未被 shell 消费的输入字符。这样前台程序运行期间敲下的空行不会在程序结束后继续触发新的 shell 提示符。

### 与 Console 的协作

为了支持这些 shell 功能，console 层做了几项配合：

- 每收到一个字符就更新 `cons.w = cons.e` 并唤醒读取者，使用户态可以逐字符读取。
- 只回显可打印字符和换行，退格、Tab、`Ctrl-U` 等控制字符交给 shell 处理。
- K210 平台下过滤多余的 `\r`，避免一次回车产生两次输入。
- 对方向键产生的 ANSI 转义序列不回显，让 shell 解析而不是在终端上显示 `[A`。
- 提供 `CONSOLE_IOCTL_FLUSH_INPUT`，供 shell 在前台程序结束后清空残留输入。

### 使用效果

优化后的 shell 支持以下交互：

- 输入文件名前缀后按 Tab，可以补全当前目录下的程序或文件名。
- 执行一条命令后按上键，可以恢复上一条非空命令。
- 前台程序运行期间连续按回车，程序结束后不会再刷出一串空 `$`。
- 在 K210 串口环境中，方向键不会显示为裸露的 `[A`。

这些改动提升了实机调试时的可用性，也为调度实验中的 `cpuburn`、`iotest` 等命令反复执行提供了更方便的交互基础。
