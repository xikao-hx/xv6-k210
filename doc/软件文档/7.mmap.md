# mmap 内存映射架构

本文档总结当前 xv6-k210 中 mmap 的实现架构。实现参考 Linux mm 的形态，但裁剪为一个内核子集：VMA + 统一缺页分发 + 三种 backing（文件 / 匿名 / 设备 page-backed 缓冲区）+ COW + 双页表同步。

## 1. 分层架构

```text
sys_mmap / sys_munmap  (kernel/syscall/sysfile.c)   只解析 ABI，分派到 vma_map_*
        │
        ▼
   mmap VM  (kernel/vm/mmap.c)                       地址分配 / VMA / object / 统一缺页
     │    │    │
  file  anon  kbuf (device)
     │
  vma_ops.fault                                      backing 物理页的产生方式，core 不解释
```

- **syscall 层**（[sysfile.c](kernel/syscall/sysfile.c#L489)）：只解析参数，按 `MAP_ANONYMOUS` / `FD_DEVICE` 分派到 `vma_map_anon` / `vma_map_device` / `vma_map_file`。
- **核心 mm**（[mmap.c](kernel/vm/mmap.c)）：集中管理地址分配、VMA/object 生命周期、统一缺页 `vm_fault`、写回、unmap、fork、destroy。
- **kbuf**（[kbuf.c](kernel/vm/kbuf.c)）：page-backed 设备缓冲区对象（引用计数 + 页面链表）。
- **trap**（[trap.c](kernel/trap/trap.c#L49)）：把 load/store/instruction 异常翻译成 `VM_FAULT_READ/WRITE/EXEC`，调 `vm_fault`。
- **copy 路径**（[vmcopyin.c](kernel/vm/vmcopyin.c)）：`copyin/copyout/copyinstr` 逐页检查权限并 fault-in。
- **设备驱动**（`kbufdev` / `eagerdev`）：只提供 `file_operations.mmap` 回调——校验请求并设置 `vma->data`，不写 fault handler、不直接碰页表。

依赖方向：syscall/trap/proc/copy → mmap VM → backing 层。禁止 backing 反向依赖 trap/syscall/proc，禁止设备驱动自行安装用户 PTE（通过公开的 `vma_populate` API 调用除外，见 6.3）。

## 2. 关键数据结构

```c
// 每个 VMA 描述一段映射；底层资源由 object 持有
struct vma_area {
  int used;
  enum vma_type type;          // VMA_FILE / VMA_ANON / VMA_KBUF
  uint64 start;                // 页对齐，映射起始（含）
  uint64 end;                  // 页对齐，映射结束（不含）
  uint64 valid_end;            // 非页对齐的用户请求长度上界（文件末页写回边界）
  uint64 offset;               // 文件/设备 offset；VMA 拆分后同步右移
  int prot;                    // PROT_READ/WRITE/EXEC
  int flags;                   // MAP_PRIVATE/MAP_SHARED（+MAP_ANONYMOUS）
  struct mmap_object *object;
  const struct vma_ops *ops;   // backing fault handler；由 core mm 按 type 安装
  void *data;                  // 设备私数据（kbuf 指针），交给 ops->fault
};

// 类比 Linux vm_operations_struct：只负责“按页产生 backing 物理页”
struct vma_ops {
  int (*fault)(struct vma_area *vma, uint64 va, void **mem);
};

// mmap object：引用计数，fork/split 共享；VMA 只引用它
struct mmap_object {
  struct spinlock lock;
  int refcnt;
  enum vma_type type;
  struct file *file;           // FILE/KBUF 类型持有（filedup）
  struct anon_object *anon;    // ANON|SHARED 持有
};

// 共享匿名页：按索引的稀疏页槽
struct anon_object {
  struct spinlock lock;
  struct anon_page *pages;     // {index, pa} 链表
};

// 设备 page-backed 缓冲区
struct kbuf {
  struct spinlock lock;
  int refcnt;
  uint64 size;                 // 用户可见长度
  uint64 npages;               // 页数
  struct kbuf_page *pages;     // 页面链表
};
```

## 3. 地址空间布局

- `p->sz` 只覆盖普通低地址用户内存（brk/sbrk）；**mmap 不修改 `p->sz`**。
- mmap 从 `MMAP_TOP = KSTACK(0)` **向下**分配，避开 trapframe/trampoline 与进程内核页表中的 kernel stack。
- `growproc` 检查 VMA 下界（`vma_heap_limit`），低地址堆增长不能侵入 mmap 区。
- 每个驻留 VMA 页必须**同时在用户页表和进程内核页表出现或消失**（`upg2ukpg` / `vma_unmap_pages`）。

## 4. 系统调用入口

`sys_mmap`（[sysfile.c:489](kernel/syscall/sysfile.c#L489)）：

```c
if (flags & MAP_ANONYMOUS) {
  if (fd != -1 || offset != 0) return -1;      // 匿名 ABI：fd==-1、offset==0
  return vma_map_anon(p, addr, length, prot, flags);
}
if (vfile->type == FD_DEVICE)
  return vma_map_device(p, addr, length, prot, flags, vfile, offset);
return vma_map_file(p, addr, length, prot, flags, vfile, offset);
```

`sys_munmap`（[sysfile.c:522](kernel/syscall/sysfile.c#L522)）：解析 `(addr, length)` 后调 `vma_unmap`。

## 5. 核心 mm 流程

### 5.1 创建（`vma_map_create`）

统一校验：`addr == 0`（不支持 MAP_FIXED）、`length > 0`、prot 合法（**拒绝 write-only**，RISC-V 无有效 write-only 叶 PTE）、sharing 标志合法、`PGROUNDUP` 页对齐且不溢出。然后：

1. `vma_find_free` 找空闲 VMA 槽。
2. `vma_find_address` 从 `MMAP_TOP` 向下找不与现有 VMA 重叠的区间。
3. `mmap_object_create` 建 object：`VMA_FILE`/`VMA_KBUF` 持有 `filedup(file)`；`VMA_ANON|SHARED` 建 `anon_object`。
4. 填充 VMA，并按 type 安装 ops：`FILE→file_vma_ops`、`ANON→anon_vma_ops`、`KBUF→kbufdev_vma_ops`。三个 ops 表**统一放在 mmap.c**，核心不解释 backing。

### 5.2 缺页处理（`vm_fault`，统一分发）

```c
int vm_fault(struct proc *p, uint64 va, int access) {
  if ((vma = vma_find(p, va)) == 0) return -1;
  if (!vma_access_allowed(vma, access)) return -1;
  page = PGROUNDDOWN(va);
  pte = walk(p->pagetable, page, 0);
  if (pte && (*pte & PTE_V)) {                    // 已驻留
    if (access == WRITE && (*pte & PTE_COW))
      return uvmcowmalloc(p->pagetable, page) ? 0 : -1;
    return 0;
  }
  if (vma->ops == 0 || vma->ops->fault == 0) return -1;
  if (vma->ops->fault(vma, page, &mem) < 0) return -1;
  // 按 prot 组装 PTE 权限 → mappages 装用户 PTE
  // → upg2ukpg 同步内核页表 → sfence_vma()
}
```

无任何 backing type 分支——backing 如何产页完全由 `vma->ops->fault` 决定。

### 5.3 三个 fault handler（都在 mmap.c）

| handler | 行为 |
|---|---|
| `file_vma_fault` | 清零新页 → `fileread_at` 用**显式 offset**（不动 `file->off`）读入文件交集；末页截到 `valid_end` |
| `anon_vma_fault` | SHARED → `anon_page_get`（稀疏页槽，锁外分配 + 锁内二次查找去重）；PRIVATE → 新零页 |
| `kbufdev_vma_fault` | 经 `vma->data` 取 kbuf → `kbuf_page_get(index)`（`kaddquota` 为 PTE 加页面引用） |

### 5.4 写回

- 仅 `VMA_FILE | MAP_SHARED | PROT_WRITE` 的**已驻留**页写回。
- `vma_writeback_page` 按显式 offset 调 `filewrite_at`，长度截到 `valid_end`，防止文件末页越界写。
- PRIVATE 页永不写回。

### 5.5 munmap（`vma_unmap`）

1. **校验**：页对齐、范围合法、至少与一个 VMA 重叠。
2. **预留槽**：若发生中间拆分（一个 VMA 被切为两段）先找空闲 VMA 槽，找不到直接失败（不改页表）。
3. **写回**：对重叠区间逐页 `vma_writeback_page`。
4. **拆 VMA**：整删 / 头裁 / 尾裁 / 中间拆分。头裁与拆分时 `offset` 同步 `+= (finish - old.start)`（否则文件 offset 错位）。
5. **拆页**：`vma_unmap_pages` 先 `uvmunmap(kpagetable, dofree=0)` 再 `uvmunmap(pagetable, dofree=1)`——归还每 PTE 物理引用。
6. 最后 `sfence_vma()`。

### 5.6 fork / exec / exit

- **fork**（`vma_fork`）：复制 VMA 结构 + `mmap_object_get`；对已驻留页，`MAP_PRIVATE | PTE_W` 页改为 **COW**（清除写位、置 `PTE_COW`），其余 `mappages + kaddquota`（共享物理页）。失败 `vma_destroy_all(child)` 回滚。
- **exec**：在替换地址空间的不可失败提交点 `vma_destroy_all`。
- **exit**：`vma_destroy_all`——写回 SHARED FILE、拆页、`mmap_object_put`（引用归零 → `fileclose` → 设备 close → kbuf 回收）。

## 6. 设备映射

### 6.1 kbuf（kernel/vm/kbuf.c）

- `kbuf_create(size)`：open 时一次性分配 `PGROUNDUP(size)` 个清零页，持有**页面基础引用**。
- `kbuf_page_get(index)`：取页并 `kaddquota`（为调用方 PTE 增加一个物理引用）。
- 引用计数：`kbuf_get`/`kbuf_put`，归零时 `kbuf_destroy` 释放所有页。

### 6.2 kbufdev —— lazy 设备

`vma_map_device` 采用 Linux `mmap_region` 形态：**先建 VMA/object，再调 `file->ops->mmap(file, vma, offset)`**，由驱动校验并配置 VMA；失败 `vma_unmap` 回滚。

```c
// kernel/devsw/kbufdev.c —— 驱动只做校验 + 设 data
kbufdev_mmap(file, vma, offset) {
  // 校验 kbuf != 0、MAP_SHARED、无 PROT_EXEC、
  // offset 页对齐、length 合法、offset+length <= kbuf_size(kbuf)
  vma->data = kbuf;        // 交给 core-mm 的 kbufdev_vma_fault
  return 0;
}
```

页在**首次访问时**由 `vm_fault` 经 `kbufdev_vma_fault` 缺页装入（lazy）。

### 6.3 eagerdev —— eager 设备（驱动直接调 `vma_populate`）

`vma_populate`（[mmap.c:521](kernel/vm/mmap.c#L521)）是 core mm **对外暴露给驱动的公共 API**，类比 Linux `remap_pfn_range`：

- 驱动在自己的 `f_op->mmap` 回调中调用它，一次性为 VMA 装好所有页（`ops->fault` 取页 → `mappages` 用户 PTE → `upg2ukpg` 内核 PTE）。
- **成功末尾 `vma->ops = 0`**：映射全驻留、fault handler 撤离，此后访问未驻留范围是硬错误（进程被杀）——测试正是靠这一点证明“真无缺页”。
- **失败回滚**：`vma_unmap_pages` 拆掉已装页，返回 -1，驱动应使 mmap 失败。

```c
// kernel/devsw/eagerdev.c —— 与 kbufdev 结构相同，但 mmap 回调直接 populate
eagerdev_mmap(file, vma, offset) {
  // 同样的 flags/prot/offset/length 校验
  vma->data = kbuf;
  if (vma_populate(myproc(), vma) < 0) {
    printf("mmap vma_populate failed\n");
    return -1;
  }
  return 0;
}
```

open 时 `kbuf_create` 直接分配全部页（“驱动直接分配内存”），eager 只是把缺页时刻**提前到 mmap 时刻**，不新增分配路径。

### 6.4 设备映射生命周期

- mmap object 持有 `filedup` 设备文件（不是 kbuf 引用）→ **close fd 后映射仍有效**。
- 最后一个 object 引用释放 → `fileclose` → 设备 `close` → `kbuf_put` 回收。
- 每个驻留 PTE 单独持有 kbuf 页的物理引用（`kbuf_page_get` 的 `kaddquota`），unmap 时 `dofree=1` 归还。

## 7. 双页表同步

用户页表与进程内核页表对每个驻留 VMA 页保持一致：

- 安装：`upg2ukpg(p->pagetable, p->kpagetable, page, page + PGSIZE)`（vm_fault / vma_populate / vma_fork）。
- 拆除：`vma_unmap_pages` 先内核页表 `dofree=0`（内核页表不持有物理引用），再用户页表 `dofree=1`（归还最后引用）。

## 10. 已知限制与边界

- **共享文件页不跨进程共享**：`file_vma_fault` 每次缺页直接 `fileread_at`，两个进程分别 fault 同一文件页得到不同物理页。共享文件页缓存（重构方案中 Step 5 提及）不在当前 master 工作区。
- 无硬件 dirty bit、`msync`、`mprotect`、`swap`、`MAP_FIXED`、完整 Linux page cache。
- `p->sz` 与 mmap 高地址区互相不感知，`growproc` 通过 `vma_heap_limit` 防侵入。
- 设备缓冲区是非连续 page-backed 内存；连续 DMA/CMA 与 MMIO 映射（真正的 `remap_pfn_range` 场景）未纳入本轮。
- 内核代码无 FPU；本模块全部为整数运算。
