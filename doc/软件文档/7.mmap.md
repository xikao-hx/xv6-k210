# mmap 内存映射架构

本文档描述 xv6-k210 当前的 mmap 实现。该实现采用 VMA、引用计数
`mmap_object` 和 backing fault handler，将文件、匿名内存和设备 kbuf 三类
backing 分开管理，并支持 COW、部分 munmap、双页表同步及 fd 关闭后的映射存续。

## 1. 代码结构

```text
sys_mmap / sys_munmap
        │
        ├── vma_map_file()   ── mmap_file.c
        ├── vma_map_anon()   ── mmap_anon.c
        └── vma_map_device() ── mmap_kbuf.c
                    │
                    ▼
             mmap.c 核心层
   VMA 地址管理 / object 引用计数 / fault 分派
   populate / unmap / fork / destroy / 双页表同步
```

相关文件：

- [sysfile.c](../../kernel/syscall/sysfile.c)：解析 mmap/munmap 系统调用参数并选择 backing。
- [mmap.c](../../kernel/vm/mmap/mmap.c)：mmap 核心操作，不实现具体 backing 的产页逻辑。
- [mmap_file.c](../../kernel/vm/mmap/mmap_file.c)：文件映射、文件 fault 和共享映射写回。
- [mmap_anon.c](../../kernel/vm/mmap/mmap_anon.c)：匿名映射和共享匿名页管理。
- [mmap_kbuf.c](../../kernel/vm/mmap/mmap_kbuf.c)：设备映射、kbuf 页容器及 eager populate。
- [mmap.h](../../kernel/include/mmap.h)：对 syscall、trap、proc 和驱动可见的公共类型与接口。
- [mmap_internal.h](../../kernel/include/mmap_internal.h)：仅供 mmap 子系统各实现文件使用的内部接口。
- [trap.c](../../kernel/trap/trap.c)：把 load/store/instruction page fault 转为 `vm_fault`。
- [vmcopyin.c](../../kernel/vm/vmcopyin.c)：让 `copyin/copyout/copyinstr` 可以按权限 fault-in VMA 页。

设备驱动只通过 `file_operations.mmap` 校验并配置 VMA，不创建
`mmap_object`、不管理 object 引用计数，也不直接安装用户 PTE。

## 2. 核心数据结构

### 2.1 VMA

```c
struct vma_area {
  int used;
  enum vma_type type;          // VMA_FILE / VMA_ANON / VMA_KBUF
  uint64 start;                // 页对齐的起始地址，包含
  uint64 end;                  // 页对齐的结束地址，不包含
  uint64 valid_end;            // 用户请求的实际长度上界
  uint64 offset;               // 文件或设备 backing 偏移
  int prot;                    // PROT_READ / PROT_WRITE / PROT_EXEC
  int flags;                   // MAP_PRIVATE / MAP_SHARED / MAP_ANONYMOUS
  int populate;                // mmap 返回前是否预先安装所有页
  struct mmap_object *object;
  const struct vma_ops *ops;
};
```

`valid_end` 与 `end` 的用途不同：`end` 用于页表范围管理，`valid_end` 保留用户
传入的非页对齐长度，用于文件末页读取和写回边界。

`populate` 由设备 mmap 回调设置，实际 populate 操作由 mmap kbuf backing 在
object 建立之后执行。驱动不直接调用内部的 `mmap_populate`。

### 2.2 mmap object

```c
struct mmap_object {
  struct spinlock lock;
  int refcnt;
  enum vma_type type;
  struct file *file;           // FILE/KBUF object 持有 filedup 引用
  struct anon_object *anon;    // MAP_SHARED anonymous object
  struct kbuf *kbuf;           // 每次设备 mmap 独立创建
};
```

VMA 管理虚拟区间，object 管理 backing 生命周期。fork 或 VMA 中间拆分会增加
同一个 object 的引用；最后一个 VMA 引用消失时，`mmap_object_put` 才销毁
backing。

object 不存放在 `struct file` 中。一次成功的 mmap 创建一个 object，因此同一个
fd 多次 mmap 会得到多个 VMA 和多个 object。对于设备映射，每个 object 还拥有
独立的 kbuf；只有 fork 和同一 VMA 的拆分才共享原 object。

### 2.3 backing ops

```c
struct vma_ops {
  int (*fault)(struct vma_area *vma, uint64 va, void **mem);
};
```

核心 `vm_fault` 只负责权限检查、调用 `vma->ops->fault` 和安装 PTE，不解释
backing 如何产生物理页。三个 ops 实例分别是各 backing 文件内的私有对象。

## 3. 地址空间与双页表

- `p->sz` 只描述普通低地址用户内存，mmap 不修改 `p->sz`。
- mmap 从 `MMAP_TOP = USER_STACK_BOTTOM` 向下寻找空闲区间。
- `vma_heap_limit` 限制 `growproc`，防止堆增长进入 mmap 区。
- 每个驻留 VMA 页同时存在于用户页表和进程内核页表。
- 安装用户 PTE 后通过 `upg2ukpg` 同步进程内核页表。
- 解除映射时先用 `dofree=0` 删除内核页表映射，再用 `dofree=1` 删除用户
  映射并归还物理页引用。

## 4. 系统调用分派

`sys_mmap` 解析：

```c
mmap(addr, length, prot, flags, fd, offset)
```

分派规则：

1. 设置 `MAP_ANONYMOUS` 时要求 `fd == -1 && offset == 0`，调用
   `vma_map_anon`。
2. 非匿名映射先从当前进程 fd 表取得 `struct file`。
3. `FD_DEVICE` 调用 `vma_map_device`。
4. 普通 `FD_ENTRY` 调用 `vma_map_file`。

`sys_munmap` 只解析 `(addr, length)`，资源释放统一交给 `vma_unmap`。设备
close 和 munmap 是两个不同的生命周期事件，关闭 fd 不会主动解除 VMA。

## 5. mmap 核心层

### 5.1 VMA 创建

`mmap_map_create` 完成所有 backing 共用的工作：

1. 当前只接受 `addr == 0`，不支持 `MAP_FIXED`。
2. 校验 length、prot 和 PRIVATE/SHARED 标志。
3. 拒绝 write-only 映射，因为 RISC-V 不支持有效的 write-only 叶 PTE。
4. 将映射长度向上按页对齐。
5. 查找空闲 VMA 槽，并从 `MMAP_TOP` 向下寻找无重叠地址。
6. 填充 VMA，绑定 backing 提供的 object 和 ops。

`mmap_object_create` 和 `mmap_object_put` 位于核心层，负责统一引用计数，并按
`VMA_FILE/VMA_ANON/VMA_KBUF` 调用对应 backing 的初始化或销毁函数。这些接口
只声明在 `mmap_internal.h`，设备驱动不可见。

### 5.2 缺页分派

`vm_fault` 的流程为：

1. 用 fault VA 查找 VMA，并按 fault 类型检查 `PROT_*` 权限。
2. 若 PTE 已驻留且是写 COW fault，调用 `uvmcowmalloc`；否则直接成功。
3. 调用 `vma->ops->fault(vma, page, &mem)` 取得带有一个 PTE 引用的物理页。
4. 按 VMA prot 生成 PTE flags 并调用 `mappages`。
5. 调用 `upg2ukpg` 同步进程内核页表，最后执行 `sfence_vma`。

核心路径没有 file/anon/kbuf 的 fault 分支，具体行为由 ops 决定。

### 5.3 eager populate

`mmap_populate` 使用 VMA fault handler 依次取得所有 backing 页并安装 PTE。
成功后将 `vma->ops` 清零，表示该 VMA 必须保持完全驻留；此后若仍发生缺页，
将作为非法访问处理。失败时会删除本次已经安装的页。

该函数属于 mmap 内部接口。设备驱动只设置 `vma->populate = 1`，由
`vma_map_device` 在创建 kbuf object 后调用它。

### 5.4 munmap

`vma_unmap` 支持整段删除、头部裁剪、尾部裁剪和中间拆分：

1. 校验地址页对齐、范围不溢出且至少命中一个 VMA。
2. 中间拆分前预留一个空闲 VMA 槽，避免修改到一半才失败。
3. 文件 backing 对需要解除的共享可写驻留页执行写回。
4. 从用户页表和进程内核页表删除目标页。
5. 更新 VMA 边界；头裁和右侧拆分同时调整 `offset`。
6. 整段删除时 put object；中间拆分时两个 VMA 共同引用原 object。

### 5.5 fork、exec 与 exit

- fork 复制 VMA 并对每个 object 执行 `mmap_object_get`。
- `MAP_PRIVATE` 的可写驻留页转为 COW；共享映射继续共享物理页。
- exec 在替换地址空间时调用 `vma_destroy_all`。
- exit 同样调用 `vma_destroy_all`，完成文件写回、页表拆除和 object put。

## 6. 三类 backing

### 6.1 文件 backing

文件映射由 `mmap_file.c` 实现：

- 只接受页对齐且在 32 位文件偏移范围内的 offset。
- 文件必须可读；共享可写映射还要求文件可写。
- 每次 mmap 创建独立 object，并通过 `filedup` 持有文件引用。
- fault 时分配并清零新页，再用 `fileread_at` 按显式 offset 读文件，不修改
  `file->off`。
- 仅 `MAP_SHARED | PROT_WRITE` 的驻留页在 munmap/exit 时通过
  `filewrite_at` 写回。
- `MAP_PRIVATE` 页不写回，fork 后按 COW 处理。

当前没有统一 page cache，因此两个独立 mmap object fault 同一文件页时会得到
不同物理页。

### 6.2 匿名 backing

匿名映射由 `mmap_anon.c` 实现：

- PRIVATE fault 分配新的清零页，fork 后通过 COW 保持父子独立。
- SHARED object 持有 `anon_object`，以页索引链表保存共享匿名页。
- 首次 fault 在锁外分配候选页，插入前在锁内二次查找，避免并发创建重复页。
- fork 和 VMA 拆分通过共享同一个 mmap object 访问相同匿名页。

### 6.3 设备 kbuf backing

设备映射及 kbuf 页容器统一位于 `mmap_kbuf.c`。`struct kbuf`、页链表和
`kbuf_create/kbuf_put/kbuf_page_get` 都是该文件的私有实现，不对设备驱动暴露。

设备 mmap 流程：

1. 核心校验文件类型、读写权限、`MAP_SHARED` 和禁止执行权限。
2. 先创建临时 VMA，使驱动回调可以检查请求并设置 `vma->populate`。
3. 调用 `file->ops->mmap(file, vma, offset)`。
4. 按 `offset + valid_length` 创建本次映射独立的 mmap object 和 kbuf。
5. object 对设备 file 执行 `filedup`，使 fd 关闭后映射仍然有效。
6. eager VMA 在 mmap 返回前 populate；lazy VMA 在首次访问时 fault-in。

kbuf 创建时一次性分配 `PGROUNDUP(size)` 个清零物理页。object 持有每个页的
基础引用；fault/populate 通过 `kbuf_page_get` 为用户 PTE 增加引用，munmap 时由
用户页表释放该 PTE 引用。最后一个 object 引用消失后释放 kbuf 的基础引用。

#### lazy kbufdev

`kbufdev_mmap` 只校验共享、非执行、offset 和长度范围，不保存 kbuf 指针。
页面在首次访问时由 `mmap_kbuf_fault` 安装。

#### eagerdev

`eagerdev_mmap` 完成相同校验后仅设置：

```c
vma->populate = 1;
```

回调返回后，`vma_map_device` 创建 object/kbuf，再由 mmap 核心完成全部页安装。

#### OLED framebuffer

OLED framebuffer 同样使用 eager kbuf。一次 mmap 必须满足 offset 为 0、长度为
`OLEDFB_FB_SIZE`、`MAP_SHARED` 且不可执行。

刷新 ioctl 的参数是 mmap 返回的用户 VA：

```c
fb = vma_device_page_address(myproc(), file, arg, 0);
```

该函数以 `(proc, file, user_va)` 查找 VMA，验证 VA 必须等于 VMA 起始地址、
backing 类型必须为 KBUF、object 必须绑定同一个 file，然后返回指定 kbuf 页的
内核地址。这样驱动不保存 `file->mmap_object`，也不依赖“一个 fd 只有一次 mmap”
的错误假设。

## 7. fd、VMA 与 object 生命周期

```text
open fd
   │
   ├── mmap A ── VMA A ── object A ── kbuf/file/anon backing
   │
   └── mmap B ── VMA B ── object B ── 独立 backing

fork 或 VMA 拆分：增加原 object 引用
close(fd)：只释放 fd 持有的 file 引用
munmap/exit：释放 VMA 持有的 object 引用
最后一个 object 引用：释放 backing，并归还 object 持有的 file 引用
```

因此：

- 同一个 fd 多次 mmap 是多次独立映射，而不是从 `file` 查找单例 object。
- close(fd) 后已有映射继续有效，因为 FILE/KBUF object 持有 `filedup` 引用。
- 真正结束某段映射的是 munmap、exec 或进程退出。
- fork 后父子 VMA 共享 object，其最终释放取决于所有相关 VMA 是否都已销毁。

## 10. 当前限制

- 不支持 `MAP_FIXED`、`mprotect`、`msync`、swap 和完整 Linux page cache。
- 共享文件映射缺少跨 object 的统一物理页缓存。
- 没有硬件 dirty bit，符合条件的驻留共享文件页在解除映射时直接写回。
- 设备 kbuf 是非连续 page-backed 内存，不是 MMIO 映射，也不保证 DMA 物理连续。
- `vma_device_page_address` 当前要求 ioctl 传入 VMA 起始 VA，不接受 VMA 中间地址。
- 内核不保存/恢复浮点上下文，mmap 实现不得引入浮点运算。
