# uarths.c 重构方案：拆分通用 ringbuf 模块

日期：2026-08-12
范围：`kernel/driver/uarths.c`、新增 `kernel/driver/ringbuf.c`、`kernel/include/ringbuf.h`、`Makefile`
目标平台：QEMU 16550A 与 K210 UARTHS

---

## 1. 重构目标

1. 从 `uarths.c` 中拆出**通用 byte ring buffer** 模块（`kernel/driver/ringbuf.c` + `kernel/include/ringbuf.h`），对外统一提供读写、空/满/用量查询接口。
2. 让 `uarths.c` 的 RX/TX 缓冲逻辑改用该模块，消除内联重复。
3. 在不改对外公共 API（`uarths.h` 声明）的前提下，提升 `uarths.c` 可读性。

已确认的边界：ringbuf 放 `kernel/driver/`；不删除任何对外函数（含 `uartgetc`）；不改任何对外函数名；`pipe.c` 不复用 ringbuf。

---

## 2. 当前设计的问题

### 2.1 Ring buffer 逻辑内联复制约 8 处

空/满判断、索引推进 `(x + 1) % SIZE`、排空循环散落在：

- `uartstart` 排空（L142-150）
- `uart_write` 满判断阻塞（L195）
- `uart_read` 排空（L311-314）
- `uart_try_read` 排空（L349-352）
- `uartintr` 丢弃计数（L495-502）
- `uart_get_rx_stats` 手工算 used（L399-402）
- `uart_flush_rx` 重置（L386-387）

"空 / 满 / 用了多少 / 还能写多少" 这些本应是 ring buffer 的原语，改一处索引规则要同步改 8 处。

### 2.2 容量 off-by-one 语义混乱

`UART_RX_BUF_SIZE 32768` 是数组大小，但满判断 `(w + 1) % SIZE == r` 要留一格，实际可用 32767；`uart_get_rx_stats` 报 capacity 用 `UART_RX_BUF_SIZE - 1`，与宏名对不上。满判断写成 `((uart.tx_w + 1) % UART_TX_BUF_SIZE) == uart.tx_r`（双层括号 + 取模），是经典陷阱。

### 2.3 `struct uart_state` 职责混杂

一个结构装了 rx 锁/缓冲/读写指针 + rx 控制标志（dropped/epoch/cancel_pending/polling/observer）+ tx 锁/缓冲/读写指针 + 硬件配置（requested_baud）。rx 与 tx 的锁都叫 lock，索引 r/w 不带前缀无法区分。

### 2.4 `uartintr` 是大杂烩（L460-508）

TX 服务 + RX 排空 + observer 回调 + 丢弃计数 + 唤醒 + poll 模式 guard 全在一个函数。

### 2.5 阻塞读写等待循环难懂

- `uart_read`（L286-309）：cancel 判断出现两次（L288、L300），epoch 判断夹在循环中间，返回 -1/0 语义靠猜。
- `uart_write`（L195-206）：panic / 可中断 sleep / 不可中断 sleep 三种出口叠在一个 while。

### 2.6 魔法数字与行为无注释

- `uart_wait_tx_idle`（L255）：`(20UL * freq) / baud + 1000`、500000 上限来源不明。
- `uart_set_baud`（L417-428）：只排空硬件 FIFO、保留软 ring 的行为无注释。

### 2.7 风格小瑕疵

`if(uart.rx_cancel_pending) {`（L288、L300）缺空格、`uart_write` 满判断双层括号等。

## 3. 目标结构

### 3.1 新增通用 ringbuf 模块

`kernel/include/ringbuf.h` + `kernel/driver/ringbuf.c`

- **纯数据结构、不加锁**：谁持锁谁调用，匹配当前 UART 锁模型。
- 数组分配 `capacity + 1`，用预留一格区分空/满；`capacity()` 直接返回真实可用数，消除 off-by-one。

```c
struct ringbuf {
  uint8 *buf;
  uint   capacity;   /* 可用字节数，数组实际分配 capacity + 1 */
  uint   head;       /* 读指针 */
  uint   tail;       /* 写指针 */
};

void ringbuf_init(struct ringbuf*, uint8 *buf, uint capacity);
uint ringbuf_capacity(const struct ringbuf*);
uint ringbuf_used(const struct ringbuf*);
uint ringbuf_free(const struct ringbuf*);
int  ringbuf_is_empty(const struct ringbuf*);
int  ringbuf_is_full(const struct ringbuf*);
int  ringbuf_push(struct ringbuf*, uint8 c);    /* 满返回 0 */
int  ringbuf_pop(struct ringbuf*, uint8 *out);  /* 空返回 0 */
void ringbuf_reset(struct ringbuf*);
```

### 3.2 uarths.c 改造后骨架

```
硬件抽象层（保留现状，QEMU 16550A vs K210 UARTHS）
  uart_hw_getc / uart_hw_tx_ready / uart_hw_putc
  uart_hw_set_rx_interrupt / uart_hw_set_tx_interrupt
  uart_hw_drain_fifo()          // 新增：从 flush_rx / set_baud 提取

struct uart_rx { spinlock lock; ringbuf ring; dropped; epoch;
                 cancel_pending; polling; observer; }
struct uart_tx { spinlock lock; ringbuf ring; }

内部服务例程（从 uartintr / uartstart 提取）
  uart_tx_service()   // 排空 tx ring → 硬件，管理 TX 中断开关，唤醒
  uart_rx_service()   // 排空硬件 FIFO → observer → rx ring，丢弃计数，唤醒
  uart_rx_wait()      // 阻塞等待"有数据 / cancel / flush"，返回原因
  uart_tx_wait_room() // 阻塞等空位，处理 panic / 可中断 sleep

对外接口：保持不变（含 uartgetc）
```

## 4. 实施步骤

1. 新建 `kernel/include/ringbuf.h`、`kernel/driver/ringbuf.c`，实现上述 API。
2. `Makefile` OBJS 增加 `$K/driver/ringbuf.o`。
3. `uarths.c`：
   - `struct uart_state` 拆为 `struct uart_rx` / `struct uart_tx`，rx/tx 数组换成 ringbuf（容量语义保持 32768 / 4096，数组各多 1 字节）。
   - 逐函数替换内联逻辑：
     - `uartstart` → `uart_tx_service`
     - `uart_write` 等待 → `uart_tx_wait_room`
     - `uart_read` → `uart_rx_wait` + `ringbuf_pop`
     - `uart_try_read` → 循环 `ringbuf_pop`
     - `uartintr` → `uart_tx_service` + `uart_rx_service`
     - `uart_get_rx_stats` → `ringbuf_used` / `ringbuf_capacity`
     - `uart_flush_rx` → `ringbuf_reset` + `uart_hw_drain_fifo`
     - `uart_set_baud` 排空硬件 FIFO → `uart_hw_drain_fifo`
4. 补注释：cancel（返回 -1）vs flush（返回 0）语义；`uart_wait_tx_idle` 的 20 字节余量；`uart_set_baud` 只排硬件 FIFO 的原因。
5. 修风格（`if(` 缺空格、双重括号）。
6. 编译验证。

---

## 5. 验证方式

- `make build platform=qemu`、`make build platform=k210` 编译通过。
- QEMU 运行：shell 回显、`consoletest`（TTY/RAW 切换、baud info、rx stats）。
- K210 烧录：shell 交互 + burn 刷 SD 全流程（覆盖 poll 模式、baud 切换、observer Ctrl-C）。
- 注意：`capacity` 上报值从 32767 → 32768，consoletest / burn 只打印不断言，无 ABI 影响。
