# 内存布局重构方案：用户/内核地址空间分离

日期：2026-08-13  
范围：进程虚拟地址空间布局、内核页表（kpagetable）映射、用户栈/堆/mmap 区域划分  
目标平台：QEMU 与 K210

---

## 1. 目标定位

本次重构将当前"用户空间与内核空间交织"的地址布局，整理为标准的分离式布局：

- **用户空间**：`[0x0, MAXUVA)`，内部按"ELF → 堆 → mmap → 栈"三段式划分，各区域上下限互不侵犯。
- **内核空间**：`KERNBASE` 起恒等映射的内核代码/数据，设备映射与 trampoline 等结构上移到高地址，与用户空间在 Sv39 L2 页表层天然隔离。

参考实现：`reference/xv6-k210`（`VIRT_OFFSET`、`MAXUVA`、`VKSTACK` 方案）。

已确认的决策：

1. 用户堆（`p->sz` / sbrk）紧跟用户程序 text/data，从下向上增长——栈移走后该语义自然成立，无需额外机制。
2. `MAXUVA = 0x80000000`（2GB，紧贴 KERNBASE），与参考实现 `RUSTSBI_BASE` 一致。

---

## 2. 现有布局与问题

### 2.1 现状布局

当前内核事实上已是"用户在下、内核恒等映射"：

- `KERNBASE = 0x80020000`（K210），内核恒等映射至 `PHYSTOP = 0x80600000`。
- trampoline / trapframe / sigtramp 在 Sv39 空间顶部（`MAXVA - PGSIZE` 附近）。
- 进程内核栈 `KSTACK(p)` 位于 trampoline 下方。

"交织"体现在三处：

### 2.2 设备映射落在用户 VA 范围内

`kernel/driver/` 各驱动用 `*_V` 宏访问设备，但当前 `*_V == 物理地址`（恒等映射）：

- UART0/GPIOHS 在 `0x38000000`，SYSCTL/SPI 在 `0x50000000~0x54000000`，全部低于 `MAXVA`，位于"本应属于用户空间"的地址区间。

**隐患**：进程内核页表 `kpagetable` 中这些设备映射与用户页共存。`upg2ukpg()`（`kernel/vm/vm.c`）同步用户页时对 `kpagetable` 直接覆写 PTE：

```c
* k_pte = (*u_pte) & ~PTE_U;   // 覆盖写，不检查是否已是设备/内核 PTE
```

若用户堆/mmap 长到设备地址，会把设备 PTE 悄悄冲掉。当前 6MB 物理内存碰不到，但架构上是错的。

### 2.3 mmap 区与内核侧结构挤在顶部

- `MMAP_TOP = KSTACK(0)`（`kernel/include/mmap.h`），即 trampoline/trapframe 附近。
- `vma_find_address()` 从 `MMAP_TOP` **向下**找空闲区间，且强制 `start >= PHYSTOP`（`kernel/vm/mmap.c`）。
- 首个 VMA 落在**最高处**，后续 VMA 依次向下——mmap 区与内核侧结构混在一起，不是标准用户态布局。

### 2.4 用户栈紧贴堆

`exec()` 将用户栈作为 `sz + 2*PGSIZE` 分配在 ELF 之后（`kernel/proc/exec.c`），栈与堆共用 `p->sz` 增长语义，而非标准 xv6 的"栈在用户空间最高地址"。

## 3. 目标布局

### 3.1 布局图

```
0x0000_0000  ┌─────────────────────┐
             │ ELF text / data     │
             ├─────────────────────┤
             │ 堆 (sbrk / p->sz) ↑ │  ← 上限 MMAP_BASE
             ├─────────────────────┤
             │       unused        │
             ├─────────────────────┤  MMAP_BASE
             │ 先创建的 mmap VMA    │
             ├─────────────────────┤  ↑ 从下向上增长，首个 VMA 在底部
             │ 后创建的 mmap VMA    │
             ├─────────────────────┤  MMAP_TOP(=栈下界，预留 guard)
             │ 用户栈 / guard page  │  ↓ 从 MAXUVA 向下
0x8000_0000  ├─────────────────────┤  MAXUVA（用户空间上限，用户不可达）
             ├─────────────────────┤  RustSBI（0x80000000~0x80020000）
0x8002_0000  ├─────────────────────┤  KERNBASE：内核 text/data（恒等映射）
0x8060_0000  ├─────────────────────┤  PHYSTOP：kalloc 池 [etext, PHYSTOP)
             ├─────────────────────┤
0x3F00_0000+ ├─────────────────────┤  设备映射（*_V = 物理 + VIRT_OFFSET）
0x3EC0_0000  ├─────────────────────┤  VKSTACK（或保留现有 KSTACK(p)）
0x3FFF_F000  ├─────────────────────┤  SIGTRAMP / TRAPFRAME / TRAMPOLINE
```

### 3.2 数值表（K210）

| 区域 | 地址 | 说明 |
| --- | --- | --- |
| 用户 ELF | `0x0` 起 | 低地址 |
| 堆（sbrk） | ELF 末尾 ↑ | 上限 `MMAP_BASE`，物理内存受限（约 6MB） |
| `MMAP_BASE` | `0x40000000`（待定，可调） | mmap 从底部向上增长 |
| mmap 上限 | `MMAP_TOP` = 栈下界 | 与栈之间预留 guard |
| 用户栈 | `MAXUVA` 向下 | 固定顶部 + 固定下界 |
| `MAXUVA` | `0x80000000` | 用户空间上限 |
| RustSBI | `0x80000000~0x80020000` | 用户不可达 |
| 内核 | `0x80020000` 恒等映射 | 不变 |
| kalloc 池 | `etext` ~ `PHYSTOP(0x80600000)` | 不变 |
| 设备映射 | `物理 + 0x3F00000000` | `VIRT_OFFSET` |
| kstack / trampoline | Sv39 空间顶部 | 不变 |

### 3.3 关键不变式

```
堆顶 < MMAP_BASE ≤ mmap 区 < 栈下界 < MAXUVA ≤ 内核/设备映射区
```

## 4. 分项方案

### 4.1 设备映射上移

做法与参考实现一致：引入 `VIRT_OFFSET = 0x3F00000000`，重新定义：

```c
#define UART0_V   (UART0   + VIRT_OFFSET)
#define GPIOHS_V  (GPIOHS  + VIRT_OFFSET)
// ... 其余外设同理
#define CLINT_V   (CLINT   + VIRT_OFFSET)
#define PLIC_V    (PLIC    + VIRT_OFFSET)
```

改动点：

- 驱动层已统一使用 `*_V` 宏（`uarths.c`、`spi.c`、`sysctl.c`、`dmac.c`、`gpiohs.c`），**驱动代码基本不用动**。
- `kernel/vm/vm.c` 的 `kvmmap`/`ukvmmap`/`ukvmunmap` 已传 `*_V`，改动很小。
- **注意 CLINT / PLIC 当前是恒等映射**（`vm.c` 中 `kvmmap(CLINT, CLINT, ...)`），需要补 `CLINT_V`/`PLIC_V`，并核对 `plic.c` 中 PLIC 相关宏是否直接使用物理地址。

### 4.2 KERNBASE 以下为用户空间

引入 `MAXUVA = 0x80000000`（与参考 `RUSTSBI_BASE` 一致），用户空间上限：

- 关键收益：用户空间主要落在 Sv39 L2 索引低位，内核在 `L2[1]`（`0x80000000` 起），设备搬到 `L2[252]`，trampoline 在 `L2[255]`，**天然零重叠**，`upg2ukpg` 无论怎样同步都不会破坏内核/设备映射。
- 恒等映射、kalloc、链接脚本、boot 代码均无需改动。

**⚠️ 不要照搬参考实现的 exec**：参考 `exec.c` 中有

```c
for (int i = 0; i < PX(2, MAXUVA); i++) kpagetable[i] = 0;
```

当 `MAXUVA = 0x80000000` 时 `PX(2, MAXUVA) = 2`，会把 **KERNBASE 所在的 L2[1] 一并清掉**，内核在进程 kpagetable 中消失。现有 `upg2ukpg()` 按需同步方案更安全，保留之。

注意：`MAXUVA = 0x80000000` 时用户空间占 L2[0]+L2[1]，与内核共享 L2[1] 这一层中间页表（无字节重叠，`walk()`/`upg2ukpg()` 正常工作），仅不如 `0x40000000` 方案在 L2 层完全隔离。

### 4.3 用户栈移到用户空间最高地址

**这是改动最大、风险最集中的一项。**

要点：

- 栈顶是 **MAXUVA 附近（0x80000000 向下），不是 MAXVA**。trampoline/trapframe/sigtramp 仍在 `MAXVA` 顶，互不影响。
- 栈做**固定顶部 + 固定下界**：`stack_top = MAXUVA`，`stack_base = MAXUVA - MAX_STACK`（含 guard），栈区单独一组辅助函数处理拷贝/释放/同步。

波及面（凡是按 `[0, p->sz)` 遍历的地方都会漏掉栈页）：

| 位置 | 现状 | 影响 |
| --- | --- | --- |
| `exec()` 栈初始化 | 栈分配为 `sz + 2*PGSIZE` | 改为在 `stack_top` 向下分配，`p->sz` 不再含栈 |
| `uvmcopy()`（fork） | 按 `[0, sz)` 拷贝 | 栈页不拷贝 → 子进程无栈，需单独拷贝栈区 |
| `uvmfree()`/`proc_freepagetable()`（exit） | 按 `[0, sz)` 释放 | 栈页不释放 → **`freewalk()` panic**（要求叶子 PTE 全清） |
| `exec()` 旧空间清理 | `uvmunmap(kpagetable, 0, old_sz, 0)` | 栈区残留旧映射，需单独清理 |
| `upg2ukpg(pagetable, kpagetable, 0, sz)` | 全部同步点 | 需扩展覆盖栈区 |

懒分配判定需重写：当前 `usertrap()` 与 `faultin_page()` 用

```c
va < p->sz && va > PGROUNDUP(p->trapframe->sp)
```

判定"堆/栈区"（`kernel/vm/vm.c`、`kernel/trap/trap.c`）。栈移顶后栈 VA **不再 `< p->sz`**，必须新增独立判定 `stack_base <= va < stack_top`。信号帧压栈（copyout 到用户栈）也要命中新判定。

### 4.4 mmap 移到用户空间、从下向上增长

- 当前：`MMAP_TOP = KSTACK(0)`，`vma_find_address()` 从顶部向下找，首个 VMA 在最高处，且强制 `start >= PHYSTOP`。
- 目标：固定 `MMAP_BASE`（如 `0x40000000`），从下向上找，首个 VMA 在底部，mmap 上限为栈下界（预留 guard）。

改动点：

- `vma_find_address()`（`kernel/vm/mmap.c`）：搜索方向改为向上，下界 `MMAP_BASE`，上界 `stack_base`（去掉 `start >= PHYSTOP`）。
- `MMAP_BASE`/`MMAP_TOP` 常量（`kernel/include/mmap.h`）：`MMAP_TOP` 改为栈下界。
- `vma_heap_limit()`：堆上限 = 最低 VMA start 或 `MMAP_BASE`。
- `vma_unmap()` 的 `addr >= MMAP_TOP` 边界校验随之更新。

### 4.5 用户堆紧跟用户代码数据向上增长

已确认语义：堆（`p->sz` / sbrk）紧接用户程序 text/data，从下向上增长，上限 `MMAP_BASE`。

- 栈移走后该语义自然成立，**无需额外机制**。
- 实施时只需保证 `growproc()` 以 `MMAP_BASE`（或最低 VMA）为堆上限，与 `vma_heap_limit()` 一致。

---

## 5. 实施顺序

按依赖与风险排序：

1. **4.2 MAXUVA 上限**：纯新增约束，零破坏，最先做。
2. **4.1 设备映射上移**：改动小、收益明确（消除 `upg2ukpg` 覆写隐患）。
3. **4.4 mmap 改方向**：中等改动。
4. **4.3 用户栈上移**：改动最大，涉及多个"隐藏假设"，单独一个阶段、单独验证。

---

## 6. 验证方法

- 构建并运行基础用户程序：`init`、`sh`、`fork`/`exec`/`exit` 循环。
- 覆盖栈区：深层递归/大局部变量触发栈缺页；栈溢出应触发 kill 而非破坏相邻区域。
- 覆盖堆区：`sbrk` 大块分配至接近 `MMAP_BASE`，确认与 mmap 不相交。
- 覆盖 mmap：多段 mmap/munmap，确认从底部向上、不与堆/栈相交。
- `procdump`（`^P`）观察多进程共存时的 kpagetable 同步正确性。
- QEMU 与 K210 双平台各跑一遍。
