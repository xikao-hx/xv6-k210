# I2C 与 SPI 中断模式重构方案：删除总线轮询，参考 uart 的中断驱动模式

日期：2026-08-15
范围：`kernel/driver/i2c.c`、`kernel/include/i2c.h`、`kernel/driver/spi.c`、`kernel/include/spi.h`、
`kernel/include/memlayout.h`（补 I2C/SPI 中断号）、`kernel/board/i2c_board.c`/`spi_board.c`（仅结构体会话）
目标平台：K210（SPI/I2C 为 K210 专用驱动；QEMU 走 virtio，不涉及）

---

## 1. 重构目标

1. I2C/SPI **新增中断模式**，**删除总线轮询**：去掉 `i2c_wait_done()` 对 `status/txflr/rxflr` 的忙等、
   去掉 `spi_dw_poll_transfer()` 对 `rxflr/txflr` 的双循环忙等。
2. **参考 uart 的中断驱动模式**：硬件进度由 ISR 推进，调用方阻塞等待完成标志（`sleep` + `wakeup`），
   ISR 只做轻量搬移、绝不 sleep。
3. **保留 DMA 路径**（与 uart 的 INT/DMA 双模式一致）：采用**阈值自动选择**——大帧（如 SD 512B 块）走 DMA，
   小帧（命令/寄存器访问）走中断；不新增模式切换 ioctl。
4. 中断注册走现有 `irq_register(irq, handler, ctx)` 注册表（`kernel/trap/irq.c`），`irq_dispatch` 统一分发。

已确认的边界（与用户讨论达成）：
- **DMA 保留**，删除的只是对总线寄存器忙等的轮询路径。
- **模式选择用阈值自动路由**（`len>=阈值→DMA，否则→中断`），不加 ioctl。
- **启动早期自适应等待**：scheduler 就绪前（无进程可 sleep）自旋等 ISR 置完成标志；有进程则 `sleep`。

## 2. 现状与问题

### 2.1 当前是纯轮询 / DMA，CPU 在慢速总线上空转

- **I2C**：`i2c_send_data`/`i2c_recv_data`（i2c.c L143/L248）按 8 字节 FIFO 分块写命令字，
  每块后调 `i2c_wait_done()`（L37）自旋等 `!ACTIVITY && TFE`。I2C 是慢总线：129 字节 OLED 帧
  在 400kHz 下需 ~2.9ms，期间 CPU 全程空转（i2c.c L23-25 注释已标注该代价）。
- **SPI**：`spi_dw_poll_transfer()`（spi.c L241）双循环轮询 `rxflr`（排空 RX）+ `txflr`（补 TX），
  每搬 32 帧空转一轮，`SPI_POLL_WAIT_TIMEOUT` 10^7 次兜底。

### 2.2 调用上下文：I2C 恒有进程可 sleep；SPI 存在启动早期窗口（本次重构的核心约束）

调用方盘点：

| 调用方 | 路径 | 上下文 | 可否 sleep |
|---|---|---|---|
| I2C0 OLED（SSD1306） | `i2cdev_ioctl` → `i2c_transfer` | 用户进程 syscall | ✅ |
| I2C1 MPU6050 | 同上 | 用户进程 syscall | ✅ |
| oledfb（游戏帧缓冲） | `oledfb_ioctl`/`write` → `i2c_transfer` | 用户进程 syscall | ✅ |
| SPI0 SD 卡（文件系统） | `sdcard_*` → `spi_write`/`spi_read` | 进程上下文（fs 操作） | ✅ |
| SPI1 W25Q64 | `spidev_ioctl` | 用户进程 syscall | ✅ |
| **SPI0 SD 卡（启动）** | `main→disk_init→sdcard_init` | **scheduler 就绪前，无进程** | ❌ |

启动时序（main.c 实测，K210）：
`consoleinit → kinit → ... → trapinit/trapinithart → plicinit/plicinithart → sbi_set_mie()（L54，开 M 模式外部中断）→ binit → spidev_init（注册 SPI IRQ，irq_register 自使能）→ i2cdev_init → sdcarddev_init → disk_init（L67，读 SD 卡）→ userinit → scheduler`

- 关键事实：`sbi_set_mie()` 在 `disk_init()` **之前**，PLIC 已就绪、SPI 中断已注册，**启动早期外部中断可正常投递**（timer 中断同样在 disk_init 期间已在触发，trap 路径已被证明可用）。
- 但 `disk_init()` 时还没有进程、没有 scheduler，`sleep()` 会 panic（sched 无进程可切）。
- SD 卡命令/响应帧（6 字节写、1~4 字节读）**小于 DMA 阈值**，无法用 DMA 绕开。
- 结论：**I2C 恒可 sleep；SPI 必须自适应等待**（有进程 sleep，无进程自旋等 ISR 置完成标志）。
  这正是本次重构与 uart 的最大不同点。

### 2.3 中断号（SDK 权威表，`reference/kendryte-standalone-sdk/lib/drivers/include/plic.h`）

| 外设 | IRQ | 本项目是否启用 |
|---|---|---|
| SPI0 / SPI1 / SPI_SLAVE / SPI2 | 1 / 2 / 3 / 4 | SPI0、SPI1 |
| I2C0 / I2C1 / I2C2 | 8 / 9 / 10 | I2C0、I2C1 |
| DMA0~5 | 27~32 | CH5(32) 已被 uart RX DMA 用 |

- `spi.c` 基址表 `spi[4] = {SPI0, SPI1, SPI_SLAVE, SPI2}`（L14-19），与 IRQ 号顺序一致，
  故 `SPI0_IRQ + num` 与 `I2C0_IRQ + num` 可直接按 index 推导。
- memlayout.h 需补（K210 分支）：`SPI0_IRQ 1`、`SPI1_IRQ 2`、`I2C0_IRQ 8`、`I2C1_IRQ 9`。

### 2.4 既有 DMA 通道冲突（本次只记录，不修）

- UART1 用 DMAC CH4/CH5；SPI1 用 CH4/CH5；I2C1 用 CH4/CH5（三个 board 文件）。K210 仅 6 个 DMA 通道。
- 中断模式**不占 DMA 通道**，天然缓解该压力；DMA 模式并发仍有互踩风险。
  本次不改 board 分配，仅在文档末尾列为后续工作。

### 2.5 顺带修复：`i2c_recv_data` 恒返回 0

- i2c.c L291 `return 0;` 吞掉了 `ret`，轮询路径的错误（超时/NACK）对外不可见。
  中断模式重写后天然修复。

## 3. 目标结构

### 3.1 与 uart 中断模式的异同（说明"参考 uart"如何落地）

**相同点**：
- 经 `irq_register(irq, handler, ctx)` 注册，`irq_dispatch` 查表分发。
- 驱动内 `spinlock`（下文 `isr_lock`）协调 ISR 与阻塞等待方；ISR 内只 `acquire/release/wakeup`，绝不 sleep。
- 等待方 `sleep(chan, lk)` 阻塞，ISR `wakeup` 唤醒（参考 `uart_rx_service`/`uartintr` 的锁纪律）。

**不同点（I2C/SPI 是事务总线，不是字节流）**：
- **不需要 ring buffer**：一次传输就是一次原子事务，ISR 直接读写调用方的 bounce 缓冲
  （i2cdev/spidev 已用内核页做 bounce，sdcard 走 `spi_read`/`spi_write` 的 kmalloc 缓冲），
  传输结束即完成，没有"常驻 RX/TX 服务循环"。
- **等待需自适应**：启动早期无进程可 sleep（见 §2.2）。
- **等待需超时**：保留当前轮询路径的超时语义（I2C 设备未接/掉线不能让进程永久挂死）。

### 3.2 中断号与 ISR 注册（memlayout.h + i2c.c/spi.c）

### 3.3 等待原语：自适应等待 + 超时（本次设计的核心）

统一封装，I2C/SPI 各一份（结构体字段名不同）：

```c
/* 等待传输完成。调用前必须已持有 c->isr_lock。
 * 进程上下文：sleep(&ticks) 阻塞——ISR 完成时 wakeup(&ticks) 立即唤醒，
 *             同时每个 tick 也会唤醒用于超时判定（复用时钟 tick，见下）。
 * 启动早期（myproc()==0，无 scheduler）：先释放 isr_lock 再自旋，
 *             否则 ISR 拿不到锁置 done，死锁。
 * 返回 0=成功；-1=总线错误/超时。 */
static int
i2c_wait_xfer(struct i2c_controller *c, uint timeout_ticks)
{
  struct proc *p = myproc();
  uint start = ticks;

  for (;;) {
    if (c->xfer.done)
      return c->xfer.err;                 /* 成功或错误（err 由 ISR 填） */
    if ((uint)(ticks - start) > timeout_ticks)
      return -1;                          /* 超时：总线卡死兜底 */
    if (p) {
      sleep(&ticks, &c->isr_lock);        /* 释放并重获 isr_lock */
    } else {
      release(&c->isr_lock);              /* boot 早期：必须释放锁再自旋 */
      while (!c->xfer.done) ;             /* ISR 会拿到锁置 done */
      acquire(&c->isr_lock);
    }
  }
}
```

要点：
- **自旋路径必须先释放锁**：ISR 与等待方共用 `isr_lock`，持锁自旋 → ISR 无法进入 → 死锁。
- **超时复用时钟 tick**：K210 tick = 5ms（param.h），`ticks` 每 tick 由 `clockintr` 更新并
  `wakeup_reason(&ticks)`。等待方 `sleep(&ticks)` 每 tick 醒来一次检查 `done` 与超时；
  ISR 完成时 `wakeup(&ticks)` 提供微秒级快路径（这是 `sleep(&ticks)` 已在本仓库 sysproc.c
  sleep syscall 中用过的成熟惯用法；对其它 `&ticks` 睡眠者的假唤醒无害，它们醒来会重查条件）。
- 超时建议默认 100 tick = 500ms（I2C 400kHz 下 129 字节帧 ~2.9ms，余量充足；可调）。
- `myproc()==0` 判定启动早期：BSS 清零，scheduler 就绪前 `cpus[0].proc` 恒 0，可靠。

### 3.4 I2C 中断模式

#### 结构体扩展（i2c.h）

```c
struct i2c_controller {
  i2c_device_number_t bus_num;
  struct i2c_dw_data i2c_data;
  struct sleeplock lock;          /* 传输互斥（现有，保持不变） */
  struct spinlock isr_lock;       /* ISR 与等待方协调锁（新增） */
  struct i2c_xfer xfer;           /* 在途传输状态（新增，isr_lock 保护） */
};

struct i2c_xfer {
  const uint8 *tx_src;            /* send：源数据；recv：0 */
  uint tx_cmds;                   /* 待写 data_cmd 字数（send=数据字节数；recv=读命令数） */
  uint8 *rx_dst;                  /* recv：目标缓冲 */
  uint rx_left;                   /* 待收字节数 */
  int need_restart;               /* 本消息首字带 RESTART */
  int is_lastmsg;                 /* 末字带 STOP */
  volatile int done;              /* 传输完成（成功或出错均置位） */
  volatile int err;               /* 0=成功；<0=TX_ABRT 等错误 */
};
```

#### I2C ISR（i2c.c）

```c
void
i2c_irq(void *ctx)
{
  struct i2c_controller *c = ctx;
  volatile i2c_t *hw = i2c[c->bus_num];
  uint32 stat = hw->intr_stat;      /* 读取即快照当前 masked 中断 */
  struct i2c_xfer *x = &c->xfer;

  acquire(&c->isr_lock);
  if (stat & I2C_INTR_STAT_TX_ABRT) {
    (void)hw->clr_tx_abrt;
    x->err = -1;                                /* 具体 abort 原因可查 tx_abrt_source */
    x->done = 1;
    hw->intr_mask &= ~I2C_INTR_MASK_TX_EMPTY;   /* 中止后关 TX_EMPTY 防风暴 */
  }
  if (stat & I2C_INTR_STAT_TX_EMPTY) {
    /* TX FIFO 空：补命令字（send 写数据 / recv 写读命令），一次写满 8 深 */
    while (x->tx_cmds && (8 - hw->txflr) > 0) {
      uint32 cmd = x->tx_src ? I2C_DATA_CMD_DATA(*x->tx_src++) : I2C_DATA_CMD_CMD;
      if (x->need_restart) { cmd |= I2C_DATA_CMD_RESTART; x->need_restart = 0; }
      if (x->is_lastmsg && x->tx_cmds == 1) cmd |= I2C_DATA_CMD_STOP;
      hw->data_cmd = cmd;
      x->tx_cmds--;
    }
    if (!x->tx_cmds)
      hw->intr_mask &= ~I2C_INTR_MASK_TX_EMPTY; /* 发完，关 TX_EMPTY，等 STOP */
  }
  if (stat & I2C_INTR_STAT_RX_FULL) {
    uint n = hw->rxflr;              /* 一次排空整个 RX FIFO */
    while (n-- && x->rx_left) { *x->rx_dst++ = (uint8)hw->data_cmd; x->rx_left--; }
  }
  if (stat & I2C_INTR_STAT_STOP_DET) {
    (void)hw->clr_stop_det;
    while (x->rx_left && hw->rxflr)  /* 收尾：STOP 后 RX FIFO 残余（不足阈值部分） */
      *x->rx_dst++ = (uint8)hw->data_cmd, x->rx_left--;
    x->done = 1;
    hw->intr_mask = 0;               /* 传输结束，关全部中断 */
  }
  if (x->done)
    wakeup(&ticks);                  /* 唤醒等待方（boot 自旋不依赖，见 §3.3） */
  release(&c->isr_lock);
}
```

要点：
- `intr_stat` 读出即掩码后的活动中断，读不清除；STOP_DET/TX_ABRT 读对应 `clr_*` 清。
- `TX_EMPTY`/`RX_FULL` 是电平型中断（由 tx_tl/rx_tl 阈值决定），**必须靠掩码或排空 FIFO 让其撤销**：
  - `tx_tl = 0`：TX_EMPTY 在 FIFO 空时置位 → ISR 补满 8；补完掩码，等 STOP_DET。
  - `rx_tl = 7`：RX_FULL 在 FIFO 满 8 时置位 → 一次排 8；**不足 8 的尾帧靠 STOP_DET 收**。
- RESTART 只应挂在第一个命令字上（`need_restart` 标志位，用后即清）。
- STOP 只应挂在最后一个命令字上（`is_lastmsg && tx_cmds==1`）。
- 补字循环一次补满 8 深，减少中断次数。

#### I2C 传输函数（替换轮询版）

```c
static int
i2c_send_data_int(struct i2c_controller *c, const uint8 *buf, size_t len,
                  int need_restart, int is_lastmsg)
{
  volatile i2c_t *hw = i2c[c->bus_num];
  struct i2c_xfer *x = &c->xfer;

  acquire(&c->isr_lock);
  (void)hw->clr_tx_abrt;                    /* 清上次残留 */
  (void)hw->clr_stop_det;
  x->tx_src = buf; x->tx_cmds = len;
  x->rx_dst = 0; x->rx_left = 0;
  x->need_restart = need_restart; x->is_lastmsg = is_lastmsg;
  x->done = 0; x->err = 0;
  /* 预填首批命令字（不必等第一次 TX_EMPTY） */
  while (x->tx_cmds && (8 - hw->txflr) > 0) {
    uint32 cmd = I2C_DATA_CMD_DATA(*x->tx_src++);
    if (x->need_restart) { cmd |= I2C_DATA_CMD_RESTART; x->need_restart = 0; }
    if (is_lastmsg && x->tx_cmds == 1) cmd |= I2C_DATA_CMD_STOP;
    hw->data_cmd = cmd;
    x->tx_cmds--;
  }
  hw->intr_mask = I2C_INTR_MASK_TX_EMPTY | I2C_INTR_MASK_STOP_DET | I2C_INTR_MASK_TX_ABRT;
  int ret = i2c_wait_xfer(c, I2C_INT_TIMEOUT_TICKS);   /* 持有 isr_lock，见 §3.3 */
  hw->intr_mask = 0;                                  /* 收尾关中断 */
  release(&c->isr_lock);
  return ret;
}
```

`i2c_recv_data_int` 同理：`tx_cmds = len`（读命令数）、`tx_src = 0`（ISR 生成 `I2C_DATA_CMD_CMD`）、
`rx_dst = buf`、`rx_left = len`。

### 3.5 SPI 中断模式

#### 结构体扩展（spi.h）

```c
struct spi_dw_data {
  ...现有字段...
  /* 中断模式在途状态（isr_lock 保护） */
  uint64 rx_count;               /* 待收帧数（字节）；TX 侧复用现有 count */
  volatile int xfer_done;        /* 传输完成 */
  volatile int xfer_err;         /* RXO/TXUI 溢出等错误 */
};

struct spi_controller {
  spi_device_num_t bus_num;
  struct spi_dw_data spi_data;
  struct sleeplock lock;         /* 传输互斥（现有） */
  struct spinlock isr_lock;      /* ISR 与等待方协调锁（新增） */
};
```

说明：现有 `spi_dw_buf_tx_uint8/short/int`（spi.c L26-50）已按帧宽搬运并在 `count` 上递减，
ISR 复用它们即可；RX 侧无现成计数器，新增 `rx_count`。

#### SPI ISR（spi.c）

```c
void
spi_irq(void *ctx)
{
  struct spi_controller *c = ctx;
  struct spi_dw_data *d = &c->spi_data;
  volatile spi_t *hw = spi[c->bus_num];
  spi_transfer_width_t width = spi_get_frame_size(c->bus_num, hw);
  uint32 isr = hw->isr;

  acquire(&c->isr_lock);
  if (isr & SPI_ISR_RXO) {                 /* RX FIFO 溢出：错误收尾 */
    (void)hw->rxoicr;
    d->xfer_err = -1; d->xfer_done = 1;
    hw->imr = 0;
  } else if (isr & SPI_ISR_TXUI) {         /* TX FIFO 下溢：没喂够，错误收尾 */
    (void)hw->rxuicr;
    d->xfer_err = -1; d->xfer_done = 1;
    hw->imr = 0;
  } else {
    if (isr & SPI_ISR_TXE) {               /* TX FIFO 低于阈值：补 TX */
      while (d->count && (SPI_FIFO_DEPTH - hw->txflr) > 0) {
        switch (width) {
        case SPI_TRANS_CHAR:  spi_dw_buf_tx_uint8(d);  break;
        case SPI_TRANS_SHORT: spi_dw_buf_tx_uint16(d); break;
        default:              spi_dw_buf_tx_uint32(d); break;
        }
      }
      if (!d->count)
        hw->imr &= ~SPI_ISR_TXE;           /* 发完，关 TXE，等回声收完 */
    }
    if (isr & SPI_ISR_RXF) {               /* RX FIFO 有数据：排空 */
      while (hw->rxflr && d->rx_count) {
        switch (width) {
        case SPI_TRANS_CHAR:  spi_dw_buf_rx_uint8(d);  break;
        case SPI_TRANS_SHORT: spi_dw_buf_rx_uint16(d); break;
        default:              spi_dw_buf_rx_uint32(d); break;
        }
        d->rx_count--;
      }
      if (!d->rx_count) {                  /* 全双工：回声收完即传输完成 */
        d->xfer_done = 1;
        hw->imr = 0;
      }
    }
  }
  if (d->xfer_done)
    wakeup(&ticks);
  release(&c->isr_lock);
}
```

要点：
- **全双工完成条件**：`rx_count`（待收）归零即完成——收到帧数等于发出帧数，最后一个回声收完就结束了。
  TX 侧 `count` 先归零（掩码 TXE），RX 侧继续等回声，逻辑独立、互不阻塞。
- **RX 阈值设 0**（`rxftlr = 0`）：RXF 在 FIFO 有 ≥1 帧即触发，保证尾帧不因低于阈值而悬空；
  TX 阈值（`txftlr`）默认 0（空才补）即可，追求饱和可调 `txftlr = SPI_FIFO_DEPTH-1 = 31`。
- `isr` 读不自动清：读 `dr` 清 RXF、写 `dr` 清 TXE、读 `rxoicr/rxuicr` 清溢出/下溢。
- 中断位宏（`SPI_ISR_TXE 0x1 / RXO 0x2 / RXF 0x4 / TXUI 0x8`）需补进 spi-dw.h（当前无）。

#### SPI 中断传输函数（替换轮询版）

```c
static int
spi_dw_int_transfer(struct spi_dw_data *d, struct spi_transfer *transfer)
{
  struct spi_controller *c = spi_ctrls[d->index];
  volatile spi_t *hw = spi[d->index];
  spi_transfer_width_t width = spi_get_frame_size(d->index, hw);

  if (transfer->len % width != 0) return -1;
  if (!d->tx_buf) { d->tx_buf = kmalloc(transfer->len); memset((void *)d->tx_buf, 0xff, transfer->len); }
  d->rx_buf = transfer->rx_buf;
  d->count = d->rx_count = transfer->len;
  d->xfer_done = 0; d->xfer_err = 0;

  acquire(&c->isr_lock);
  (void)hw->icr;                            /* 清残留中断 */
  /* 预填 TX FIFO（先写一批，减少首帧空等） */
  while (d->count && (SPI_FIFO_DEPTH - hw->txflr) > 0) {
    switch (width) { /* 同 ISR 的写分发 */ }
  }
  hw->imr = SPI_ISR_TXE | SPI_ISR_RXF | SPI_ISR_RXO | SPI_ISR_TXUI;
  int ret = spi_wait_xfer(c, SPI_INT_TIMEOUT_TICKS);
  hw->imr = 0;
  release(&c->isr_lock);
  return ret;
}
```

#### __spi_transfer 路由改造（spi.c L458）

```c
if (spi_can_dma(spi_data, &xfers[i]))
  ret = spi_dw_dma_transfer(spi_data, &xfers[i]);   /* DMA 保留 */
else
  ret = spi_dw_int_transfer(spi_data, &xfers[i]);   /* 原 spi_dw_poll_transfer → 中断 */
```

删除：`spi_dw_poll_transfer()`（spi.c L241-320）、`SPI_POLL_WAIT_TIMEOUT`。
`spi_dw_dma_transfer` 保留，其内部 `dmac_wait_done` 忙等不动（与 uart TX DMA 一致，见 §6）。

### 3.6 初始化

- `i2c_init`/`spi_init`：各实例 `initlock(&ctrl->isr_lock, "i2c isr"/"spi isr")` + `irq_register(...)`。
- I2C 阈值寄存器：`i2c_dw_init` 里设 `tx_tl = 0`、`rx_tl = 7`（`I2C_RX_TL_VALUE(7)`），并保持 `intr_mask = 0`（无传输时无中断）。
- SPI 阈值寄存器：`spi_dw_init` 里设 `rxftlr = 0`、`txftlr = 0`，保持 `imr = 0`。
- 传输时按需使能中断，收尾关断——`isr_lock` 的初始化在 `irq_register` 之前完成。

## 6. 后续工作（本次不做）

1. **DMA 通道冲突**：SPI1/I2C1 与 UART1 共用 DMAC CH4/CH5。方案二选一：
   - 给 SPI1/I2C1 换空闲通道（仅 CH2/CH3 可用，与 I2C0 冲突）——空间不足，K210 仅 6 通道；
   - 或 SPI1/I2C1 弃用 DMA 全部走中断（中断不占 DMA 通道）。
   本次保持现状，仅记录。
2. **SPI/I2C 中断路径性能调优**：`txftlr`/`rxftlr`/`tx_tl`/`rx_tl` 阈值、FIFO 批量搬移粒度、首帧预填量。
3. **`dmac_wait_done` 忙等**：uart TX DMA 保留了它，SPI/I2C DMA 也保留以保持一致；
   若后续要让 DMA 也睡眠，需引入 DMAC 完成中断（CH5 IRQ=32 已被 uart RX 用，需仲裁）。
4. 若启用 SPI_SLAVE/SPI2，按基址表顺序补 `SPI_SLAVE_IRQ 3`/`SPI2_IRQ 4` 与 board 条目。
